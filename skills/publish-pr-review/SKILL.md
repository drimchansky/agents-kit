## Core Rules

1. Read `./AGENTS.md` and apply its rules — the domain-neutral core.
2. This is an engineering skill: also read `./references/engineering/rules.md` and apply it on top of the core.

Publishes one review from this session's upstream review. Invocation alone grants no publishing permission; step 4's selection authorizes the payload. Edit no code, title, PR state, or merge; publish nothing outside the selected source tiers. Include the reviewing models in the body.

## Preconditions — stop if unmet

- Require the findings source (`/review-code`'s Findings, or `/review-code-triage-verify`'s Batches) and Reviewed provenance from the latest of those runs: head SHA, merge-base SHA, and model. If absent, request `/review-code` followed by this skill. Do not review or invent findings here.
- Read Reviewed kind before lookup. Reject `paths` in one line: a path set proposes no change; publishing requires branch/PR review. Unrecognized forms: `../review-code/SKILL.md` § *Output*. <!-- cold -->
- For branch/range, match an open PR at the reviewed head through `./references/workflow/pr-lookup.md`, taking its stop outcome. Preserve the selected number. A caller that already matched and carries the selected PR supplies its number, host, and repository instead. Scope every `gh` call to that host and repository. GitHub missing the head requires push then rerun; an existing head without an exact open PR requires fresh review. Lookup authorizes no push.
- Read that number with `number,title,url,state,author,headRefOid,baseRefName`; require OPEN. Compare author.login with `gh api user --jq .login` to establish an own PR. Do not substitute the checkout's PR.
- Label the terminal session for the selected PR per `./references/workflow/terminal-session.md`.
- Require headRefOid equal to the reviewed head. A head mismatch reports `Publish stopped: head moved (<reviewed-head> -> <live-head>)` before any submission. Without a caller-supplied PR, name `/review-code` then `/publish-pr-review` as the next step. For **branch**, recompute `git merge-base <baseRefName> <headRefOid>`, fetching the base if potentially stale, and require the reviewed merge-base. A merge-base mismatch remains a distinct stop for a fresh review; correct a wrongly declared PR base before that review.
- For **range**, compare against the object's recorded base, not the PR's baseRefName. Head equality establishes no whole-PR coverage. Every range posts COMMENT and names its recorded base/head, even when it might cover the whole PR.

## Process

1. **Resolve source tiers.** From `/review-code`, tiers 1 and 2 use its Findings section: Critical/Major entries, then Minor entries. From `/review-code-triage-verify`, read Batches per `./references/workflow/verify-pipeline.md` § *Reading Batches downstream*; tiers 1 and 2 take its entries whose verdict is Confirmed, Inconclusive, or Unverified: Critical/Major entries, then Minor entries. Publish no entry that shows a triage bucket in place of a verdict. List each as skipped, with its severity, location, and bucket. A skipped Critical/Major in **verify** is unsettled. Tier 3 uses Improvements from either source. `review-pr-loop` may instead supply all three tiers after its own decision and dedupe; that supplied set replaces these sources for counts and payload construction. Never publish Withdrawn findings, a Confirmed verdict's root cause and fix options, Summary, Inaccessible context, or Cross-check detail. Keep each entry's location and full problem/recommendation/impact text verbatim. Remove `cited by k/N` corroboration markers. In a Batches entry, drop a Confirmed trailing verdict whole: its label, detail, and any `verified inline` mark. Replace a whole Inconclusive or Unverified trailing verdict with a closing note, `(Inconclusive: <what's missing>)` or `(Unverified: <reason>)`, out-of-probe-scope included, at every severity; the note posts with the claim. Step 3 normalizes the leading severity marker. Count existing entries without reviewing the diff again.

2. **Name reviewing models.** Take the model from Reviewed, dropping `×N`; do not attribute the review to the current publisher. A non-skipped Cross-check adds its cross-vendor engine (`./references/workflow/probe-cross-check.md`). <!-- cold --> Use `Reviewed by <model>`, plus `, cross-checked by <engine>` when applicable.

3. **Build selectable payloads.** Each selection includes its tier and preceding tiers.

   - Open each entry with the marker `./references/workflow/user-facing-messages.md` § *Surface adapters* assigns it for GitHub PR review comments. Strip one recognized legacy prefix or marker from the source text first, then keep the rest verbatim with its verification notes. Entries under `Not anchored to the changed lines:` take the same marker.
   - Use COMMENT when the selection contains Critical/Major or an unsettled entry exists, APPROVE otherwise. Range and own-PR overrides force COMMENT; decide both before the picker.
   - Anchor changed-line entries as `{path,line,side:"RIGHT",body}`, using LEFT for removed lines. Put unanchorable or unlocated entries under `Not anchored to the changed lines:` in the body; omit none.
   - Body contains attribution and any unanchored list, plus one-line approval for APPROVE. A COMMENT with only body entries says they are in the body rather than approving. A COMMENT with no entries carries attribution only. Range bodies additionally name the recorded base and head. Include no summary or unselected tier.
   - All tiers empty with no unsettled entry produces one-line approval plus attribution and no inline comments. For range, say the range was clean and name its coverage under COMMENT.

4. **Offer the counted tier picker.** Name every skipped entry before the options. When any tier has entries, offer `Critical/Major only — N comments`, `+ Minor — N comments (D new)`, `+ Improvements — N comments (D new)`, and `Post nothing`. N counts cumulative inline comments; D counts entries added by that tier. If body-only entries exist, show cumulative counts for both: `N comments, M in the body (D new)`, with D covering both. Keep empty tiers visible as `0 comments` or `(0 new)`. When all tiers are empty and no unsettled entry exists, offer only `Post approval — 0 comments` and `Post nothing`; for range use `Post clean review — 0 comments`. When all tiers are empty and an unsettled entry exists, post nothing: name it and `/review-code-triage-verify` as the next step. Before options on an own PR, explain every posting option becomes COMMENT because GitHub rejects self-approval. Use the host's structured question tool if available, otherwise the same numbered list in chat. Require an answer matching exactly one option; re-ask ambiguous, qualified, two-sided, bare-yes, or unmatched free-text answers without choosing a default. Selection proceeds directly to step 5 without another confirmation. Post nothing ends here with no posting call. Every posting path requires this picker, including an empty review, except the selection `review-pr-loop` pins per pass under its own gate (`./references/workflow/skill-conventions.md` § *Current members*).

5. **Recheck and post.** Repeat the live head/merge-base checks immediately before posting, applying branch/range rules above. Report a head mismatch with the named head-moved outcome and submit nothing. Without a caller-supplied PR, name `/review-code` then `/publish-pr-review` as the next step. Other drift stops for `/review-code` then `/publish-pr-review`; correct a wrong PR base first. Write scratch JSON and submit once with `gh api --method POST repos/{owner}/{repo}/pulls/<number>/reviews --input <file>`. Use the selected PR's owner and repository. Payload: `{event,commit_id,body,comments:[{path,line,side,body}]}`; commit_id is the reviewed head. Omit comments only when there are no inline entries, including on APPROVE. Remove scratch on success or failure. Add no AI/tool footer, even under an environment default. Report failed calls and stop; never retry a rejected verdict as another verdict. The own-PR COMMENT substitution was decided before consent, not after failure.
   - **Own-PR Approve fallback:** retain the selected body and inline entries but send COMMENT where APPROVE would otherwise apply. Report the self-approval limitation. Critical/Major and range selections already use COMMENT.

6. **Report.** Name PR number/title/URL, selected tier, structured or numbered-chat picker, verdict, and inline count. Name every skipped entry. Post nothing reports no call. An empty review reports that all tiers were empty and which option was selected.
