## Core Rules

1. Apply the working repository's `AGENTS.md` and `CLAUDE.md`, reading any not already in context.
2. This is an engineering skill: also read `./references/engineering/rules.md` and apply it on top of the core.

Review the object Setup resolves (the current branch's diff against its base with no argument, or the commit range, path set, or open PR the invocation names) for correctness, unintended impact, and adherence to project patterns.

## Flags

- `-g <group>`: review against one task group's Direction and Decisions. Accept a directory path or name; quote a value containing spaces. Resolve it under Setup before object resolution. Omitted means no group context. The `-x` probes remain code-only and receive no group context.
- `-n N`: launch N independent reviewers over the identical review object and pool their returns into one findings list before verdicts are assigned. Default 1, no ceiling. N is a positive whole integer; anything else stops the review with a question, and a count that reads as a stray digit is confirmed before launching. Only reviewer 1 runs the project's verification scripts, and none does on the PR form or a fork PR; every reviewer fetches the extracted links itself.
  For `-n N` above 1, apply `./references/workflow/reviewer-fleet.md` at launch, intake, pooling, and Output. <!-- cold -->
- `-x [N]`: cross-check. Launch N independent cold reviews of the same object on the cross-vendor engine and merge them before findings are finalized (`./references/workflow/probe-cross-check.md`; shape `./references/workflow/probe-shape-cold-review.md`; contract `./references/workflow/agent-fanout.md`; engine `./references/workflow/probe-engines-cross-vendor.md`). Off by default. `-x` without a count launches one, and N has no ceiling. A token directly after `-x` made only of decimal digits can be its count. Any other token, including `#<n>` or a PR URL, is not a count and goes on to object resolution. Before taking a digits token as the count, try it as a commit (`git rev-parse --verify <token>^{commit}`) and as a tracked path (`git ls-files --error-unmatch -- <token>`). When either succeeds, stop and ask whether the token is the count or the object; otherwise take it as the count. N is a positive whole integer; a count of zero stops the review with a question before anything launches, and a count that reads as a stray digit is confirmed before launching. The probes are read-only; their outcome is recorded on the `Cross-check:` line. <!-- cold -->
- `-d`: draft a PR title and description body under `./references/workflow/pr-description.md`. The session drafts on either pass; never tell the reviewer the flag is set or request a draft from it. Off by default. Render refusal as `-d refused: <reason>` in Output's **PR description** slot. <!-- cold -->

## Setup

Preserve the caller's branch, index, and working tree. Use a separate worktree or clone when the review needs another checkout. Evidence capture runs in its own disposable checkout (`./references/engineering/review-evidence.md` § *Capture*). Git writes include the PR form's `refs/pull/<n>/head` fetch (`FETCH_HEAD` only), the base fetch under `./references/workflow/pr-lookup.md` § *The PR base*, and the PR form's worktree add and remove. User-invoked and model-invoked runs both make these writes.

`review-pr-loop` may supply a selected PR number, host, repository, and expected head for a no-argument branch review. Use that number for both branch-context reads, with every `gh` call scoped to the supplied host and repository. Require each read to return `OPEN` at the expected head. A head mismatch reports only `Review stopped: head moved (<expected-head> -> <live-head>)`; lookup failure, another state, or another identity stops without falling back to branch discovery.

With supplied loop context, apply `../review-pr-loop/SKILL.md` § *Review head checks* throughout this skill, including cancellation and late-return handling. <!-- cold -->

**Resolve the group** (with `-g`). Consume its value before probing any object token. A missing value stops with a question. Apply `../start-group/SKILL.md` § *Resolve the group* steps 1–5, using the caller's working directory for relative paths. A task folder, refused path, or ambiguous or unmatched name stops with a question before any reviewer, probe, fetch, or post. Require the resolved directory to hold a `GROUP_CONTEXT.md` entry or a task below it. Otherwise ask for a group; never take start-group's Init route. Keep the selected absolute path and registered root, if any. Read no ancestor group files and write no group files.

**Resolve the object.** Consume flags, `-g`'s value, `-n`'s value, and `-x`'s count before reading the object. Take `-x`'s count only after § *Flags* finds that its token names no commit or tracked path. `--` terminates the object's own tokens, so `-- <path>… -n 3` names one path set and a count. With no argument the object is the current branch's diff against its base: run **Determine base branch** and take `<base>...HEAD`.

With an argument, select the form before applying it. Before any `--`, a bare `#<n>` token or a PR URL `https://<host>/<owner>/<repo>/pull/<n>` selects the PR form, `<n>` being decimal digits. A tracked path spelled like `#<n>` goes after `--`. The PR token must be the object's only bare token; another bare token beside it stops with a question.

A bare positional token naming a directory the recognition set in `./references/workflow/task-layout.md` § *One task, one flat folder* claims is task context.

Compare its `result.md` `**Pointers:**` branch with `git branch --show-current` from the session's own checkout. A project-local folder also requires equal `git rev-parse --path-format=absolute --git-common-dir` output at that checkout and the folder. Externally stored folders use the session repository.

When the recorded branch equals the nonempty current branch in that repository, select the no-argument branch object. Immediately run **Determine base branch** and announce `reviewing <branch> vs <base> (from task folder <slug>)` in chat. Then continue Setup's remaining identity and context work with that object's branch kind, base, and PR context.

Otherwise, stop and ask which work the folder tracks (a branch, a range, or a PR), offering the branch its `result.md` `**Pointers:**` line records (repository per `./references/workflow/task-delivery.md` § *Branch and worktree creation* → **Which repository**) and naming `/review-task` alongside; with no recorded branch, ask with no default.

Probe what remains bare both ways: as pathspecs (`git ls-files --error-unmatch -- <tokens>`), and as a rev or range by splitting the token on `...` or `..` and running `git rev-parse --verify <endpoint>^{commit}` on each side. A token that resolves both ways stops and asks. Everything after a `--` is a path set, and no other probe runs. Only once a form is selected does its own failure stop the review; an argument no form claims stops with a question.

The selected form is one of:

- **A path set:** arguments naming tracked paths under the repository root, and everything after a `--`. The object is the tracked files the index lists under those paths, from `git ls-files --error-unmatch -- <paths>`. Setup compares the index against the head commit with `git diff --cached --name-status --no-renames HEAD -- <paths>`: a staged addition (`A`) has no content at the head SHA, so record it under **Divergence** as staged-only and settle a Critical or Major finding there by the verify route `./references/workflow/agent-fanout.md` fixes; a `git rm --cached` path (`D`) is recorded under **Divergence** as dropped from the index though in the head commit; a staged edit (`M`) reads from the head SHA like any other path. An unmerged path counts once per stage in the digest. Exit 1 stops the review before anything is launched, naming every pathspec that matched nothing; any other non-zero exit is reported as the git error it is.
- **A range:** `<a>..<b>` or `<a>...<b>`, or a single rev standing for `<rev>..HEAD`, a rev being whatever `git rev-parse --verify <rev>^{commit}` accepts. Either range form reviews the diff from `merge-base(a, b)` to `b`, so echo the resolved object back before reviewing (`reviewing <merge-base>...<b>`). The single-rev form names a base by hand, but the kind is `range`, which `/publish-pr-review` posts as `COMMENT`; a review meant to approve the branch runs with no argument. **Resolve `b` to a SHA here, once** (`git rev-parse --verify <b>^{commit}`) and use that SHA everywhere `b` is recorded or compared. That merge-base is the base, so **Determine base branch** does not run, except under `-d` for its guard alone. `-d` is allowed on a range only where `b` is the current branch's HEAD **and** `merge-base(a, b)` is that branch's own base; otherwise the flag entry's refusal applies.
- **A PR:** `#<n>` or `https://<host>/<owner>/<repo>/pull/<n>`, naming an open PR of the checkout's repository. The object is the PR's head commit against its merge-base with the PR's base branch, reviewed in a detached worktree that **Resolve the PR** adds.

**Resolve the PR** (PR form only). These commands run in the caller's checkout:

- Find the repository `<host>/<owner>/<repo>`. A URL names it. For `#<n>`, first run the read and state check below under gh's default repository, then take it from the returned `url`.
- Set `GH_HOST=<host>` and `GH_REPO=<host>/<owner>/<repo>` for every later `gh` call in the run.
- Select the PR remote: the checkout's remote whose URL normalizes to that `<host>/<owner>/<repo>` under `./references/workflow/pr-lookup.md` § *The PR base*. With none, stop naming the repository and the `git remote -v` output. A URL reaches this stop before any `gh` call. <!-- cold -->
- Read the PR with `gh pr view <n> --json number,title,body,url,state,comments,reviews,headRefOid,headRefName,baseRefName,isCrossRepository`, unless the first step already read it.
- Stop before any fetch when the read finds no PR, finds a `state` other than `OPEN`, or fails with another `gh` error, such as auth or network. Report `Review stopped: PR #<n> not found`, `Review stopped: PR #<n> is <state>`, or `Review stopped: PR #<n> read failed (<error>)`.
- Fetch the head with `git fetch --refmap= --no-tags <pr-remote> refs/pull/<n>/head` under the hook-free checkout rule in `./references/engineering/review-evidence.md` § *Capture*. That ref reaches same-repository and fork heads alike. A failed fetch stops the review with `Review stopped: head fetch failed (<pr-remote>: <error>)`, naming Git's error. Where `git rev-parse FETCH_HEAD` differs from `headRefOid`, stop with `Review stopped: head moved (<read-head> -> <fetched-head>)`.
- Resolve the base SHA per `./references/workflow/pr-lookup.md` § *The PR base* with the PR remote selected above, taking its outcome.
- Create the worktree's directory with `mktemp -d <scratch>/review-pr-<n>-<short-head>.XXXXXX`, `<scratch>` being the host's scratch area, and use the path it prints as `<path>`. Add the worktree with `git worktree add --no-checkout --detach <path> <headRefOid>`, then populate it with `git -C <path> reset --hard --no-recurse-submodules`. Apply the hook-free checkout rule in `./references/engineering/review-evidence.md` § *Capture* to both commands. The populate step also passes `-c core.symlinks=false`, so committed symlinks check out as plain files holding their target path. Once that add succeeds, remove the worktree from the caller's checkout with `git worktree remove --force <path>` when the run ends, including on a later stop or failure. Before that removal, handle each launched `-x` probe through its own background command: collect it if it has finished, or stop it if it still runs there (`./references/workflow/delegated-waiting.md` §§ *Per-host primitives* and *Shell commands*). A failed populate step is such a failure and stops the review. When the add fails, remove nothing. A composite caller removes that added worktree after its own last phase instead.

The object is kind `branch` at head `headRefOid`, with base `<base-sha>` and merge-base `git merge-base <base-sha> <headRefOid>`. **Determine base branch** does not run for this form. Announce `reviewing PR #<n>: <headRefName> vs <baseRefName>` in chat.

The effective root is the tree the object lives on, and every git command in this Setup runs there. On the PR form it is the added worktree, and only **Resolve the PR** runs in the caller's checkout. On the PR form, every session read of the reviewed object after Setup runs at the effective root or uses `git show <head-sha>:<path>`. This includes settle spot-checks, the inline fallback, and composite phases that cite this skill, including triage classify and verify re-checks. On the PR form and with supplied `review-pr-loop` context, every Git command and file-tool read or search at the effective root follows the PR checkout rule in `./references/engineering/review-evidence.md` § *Capture*. The no-argument, range, and PR objects make a `pr`-kind packet; a path set makes a `paths`-kind one.

**Determine base branch** (for the no-argument object, and on a range only for the `-d` guard): with supplied loop context, read `gh pr view <number> --json state,baseRefName,headRefOid` and apply the supplied-context guards above; the context names `<host>/<owner>/<repo>`. Otherwise, read the current branch's PR with `gh pr view --json state,baseRefName,url`, taking it only when `state` is `OPEN`; its `url` names `<host>/<owner>/<repo>`. With either open PR, resolve the base SHA per `./references/workflow/pr-lookup.md` § *The PR base*, taking its outcome. Use that SHA as the base; `/publish-pr-review` resolves the same base when it re-checks. On that section's fallback, follow its declared-ref order before using local heuristics. With no open PR, or when neither fallback ref resolves, use local heuristics: common ancestors with `main`, `master`, `develop`, or `release/*`, verifying the commit count is reasonable. Announce any PR base fallback in chat as `reviewing <branch> vs <base> (PR base <baseRefName> unresolved: <reason>; possibly stale)`, naming the base used and why.

**Resolve the review object's identity:** record the **kind** (`branch`, `range`, or `paths`), the reviewed head commit (`git rev-parse HEAD`, or the SHA `b` resolved to), and its merge-base with the base. A path set has no merge-base: its identity is the head SHA and the digest `git ls-files --full-name --error-unmatch -- <paths> | LC_ALL=C sort | git hash-object --stdin`, computed at the effective root keeping `LC_ALL=C` and `--full-name` (`./references/workflow/reviewer-contract.md` § *Launch packet*).

**Launch the cross-vendor probes** (only with `-x`): start N background probes per `./references/workflow/probe-cross-check.md`, N being `-x`'s count. Each is a cold second review of that same object at the effective root, demanding findings with severity and `file:line` evidence. Start each as its own background command with its own assigned scratch directory (`./references/workflow/agent-scratch.md` § *Assignment*), per `./references/workflow/probe-engines-cross-vendor.md`. Before the first probe starts, announce the launch as one progress line (`./references/workflow/user-facing-messages.md` § *Blocks*): `🔵 In progress: cross-check (<engine> ×<N>) on <object>`, without ` ×<N>` when N is 1. Launch the probes before the review pass, continue while they run, and merge them in the Settle. On the PR form and a path set, launch them as soon as the object is resolved. On the PR form, that follows the fork-status read in **Resolve the PR**. On the no-argument object and a range, launch them once **Gather context** below finishes its PR lookups and fork-status reads. Launch no probe when a Setup PR lookup returns a PR reading `isCrossRepository` true in any state (`./references/engineering/review.md` § *Verification Scripts*), and record the outcome as `Cross-check: skipped (fork PR)`. On the PR form, each probe's prompt carries the PR checkout line from `./references/workflow/probe-shape-cold-review.md`. <!-- cold -->

**Gather context:**

- Read the object's own commit messages (`merge-base(a, b)..b` on a range).
- On the no-argument object, and on a range whose `b` is the current branch's HEAD, check for an open PR with `gh pr view --json number,title,body,state,url,comments,reviews,baseRefName,headRefOid,isCrossRepository`, taking the result as PR context only when `state` is `OPEN`; **Capture evidence**, the fork-PR scripts skip, the fork-PR reproduction and instruction-files lines, and the `-x` fork skip still read `isCrossRepository` from a result in any state. It runs on no other range. With supplied loop context, target its number and apply the supplied-context guards above. Without that context, missing `gh` or a non-GitHub remote skips the lookup, and a repository with no remote completes it with no PR. When `gh pr view` reports no pull request for the branch, read fork status at the reviewed head per `./references/workflow/pr-lookup.md` § *Fork status at a head SHA*. That read supplies no PR context.
- On the PR form, use the read from **Resolve the PR** as PR context. That step stops the review unless the PR is `OPEN`.
- On the PR form, the PR's checks replace the project's verification scripts on both passes. The session reads them after the review, under **Read the PR's checks** below.
- On a range with any other `b`, find the PR whose head is that SHA per `./references/workflow/pr-lookup.md`, naming `isCrossRepository` among its fields; this skill is its **no-stop consumer**: no match, no `gh`, or no remote means no PR context. Then read fork status at that SHA per `./references/workflow/pr-lookup.md` § *Fork status at a head SHA*. That read supplies no PR context. <!-- cold -->
- If a PR exists: read its title, description, and review threads, and extract every URL from them. The URLs travel to the reviewer, which fetches them; the session fetches them only on the inline fallback.
- With no PR, proceed on the commits and the user's context. A path set has neither: its context is whatever the user gave.
- With `-g`, give each primary reviewer the selected group's absolute path and its `GROUP_CONTEXT.md` sections `## Direction` and `## Decisions`. Each reviewer reads those sections from disk on this invocation under `./references/workflow/reviewer-contract.md` § *Launch packet*. Record absent files or sections as "none recorded". With no PR, record "no child matched because the review has no PR". Keep source paths absolute internally; Output renders them relative to the selected registered root, or absolute outside every registered root.

## Review pass

**Launch.** Unless the user explicitly asked for an in-session pass (**Inline fallback**), launch the native `reviewer` adapter with the complete Setup object under `./references/workflow/reviewer-contract.md` § *The launch*. The session puts in the packet:

- the review object named concretely (`<base>...HEAD`, `<merge-base>...<b>` with the SHA `b` resolved to, or the path set at the head SHA), never pasted diff or file text, with the identity Setup resolved
- the absolute effective working root
- one scratch directory per reviewer under `./references/workflow/agent-scratch.md` § *Assignment*: an absolute path, or `none (<reason>)` when creation fails
- the silence-watch command `node <kit-root>/scripts/silence-watch.ts` with an absolute kit root, or `none (<reason>)` when none resolves.
  Supply it under `./references/workflow/delegated-waiting.md` § *Shell commands*.
- the kind, `pr` or `paths`
- the PR context Setup gathered and every extracted URL, or an explicit `none`
- the group context from **Gather context**, or `none`, under `./references/workflow/reviewer-contract.md` § *Launch packet*
- the line `reproduction: verify route only — fork PR` in every reviewer's packet when a Setup PR lookup returns a PR reading `isCrossRepository` true in any state (`./references/engineering/review.md` § *Verification Scripts*)
- the line `instruction files: merge-base only — fork PR` in every reviewer's packet when a Setup PR lookup returns a PR reading `isCrossRepository` true in any state (`./references/workflow/reviewer-contract.md` § *Posture*)
- the line `git commands: PR checkout rule` in every reviewer's packet on the PR form and with supplied `review-pr-loop` context (`./references/engineering/review-evidence.md` § *Capture*)
- the line `git reads: stored objects only — PR-form review worktree` in every reviewer's packet on the PR form only (`./references/engineering/review-evidence.md` § *Capture*)
- the absolute paths of `references/engineering/review.md`, the checklist directory beside it, `references/engineering/rules.md`, and `CORE_RULES.md` under the install root (`./references/workflow/reviewer-contract.md` § *Adapter defaults*)
- the user's own context and constraints, verbatim, or `none`
- this skill's § *Review Focus*, verbatim
- the instruction that the reviewer builds the change map and the blast-radius search itself, and runs the project's verification scripts over the reviewed set, in the per-reviewer form `./references/workflow/reviewer-contract.md` § *Launch packet* fixes under `-n N`. On the PR form, every reviewer's packet carries `verification scripts: skip — the session reads the PR's checks` in place of the scripts instruction. Off the PR form, when a Setup PR lookup returns a PR reading `isCrossRepository` true in any state, every reviewer's packet carries `verification scripts: skip — fork PR` instead. A caller that substitutes its own evidence keeps its own skip line.

A packet with a missing or ambiguous item is completed by reading or asking, never launched short. Announce the launch as one progress line (`./references/workflow/user-facing-messages.md` § *Blocks*), `🔵 In progress: reviewer (<model>, <effort>) on <object>`, both pins read from the installed adapter (`./references/workflow/reviewer-contract.md` § *Adapter defaults*). With `-n N` above 1 that line names `reviewer ×N`.

**Wait.** While the reviewer is in flight the session runs no command against the tree: no diff reads, no scripts, no scratch runs. The loop's supplied PR context permits its remote head checks during this wait. Wait per `./references/workflow/delegated-waiting.md` § *How to wait*, reporting where each launch stands at each check-in as one progress line per launch; under `-n N` that holds until the last of the N is in. The `-x` probes are read-only and may overlap the wait.

**Settle.** The return is evidence, not a verdict; this skill assigns the verdicts per `./references/workflow/reviewer-contract.md` § *The settle*. First classify an explicit safety signal under that contract's § *Safety blocks*; it takes the **Blocked output** below, not an inline retry. Then the two intake checks, in order: the `Identity` echo against the identity Setup resolved (a mismatch means the reviewer resolved a different object: stop and report, settle nothing, launch nothing), then every return heading present (a malformed return takes the inline fallback with reason `reviewer failed`). After intake and any pooling, take **Read the PR's checks** on the PR form, then **Capture evidence**, then **Prepare finding wording** below. Then adopt, spot-check, and assign the final verdicts as that section orders; `Summary` and `Improvements` pass through uncited.
With `-x`, pool the completed probes among themselves, then merge the pooled set once (`./references/workflow/agent-fanout.md` § *Merge contract*). Render the `Cross-check:` line per `./references/workflow/probe-cross-check.md`, naming each probe that did not complete with its reason. <!-- cold -->

**Read the PR's checks** (PR form only). The session reads them per `./references/engineering/review.md` § *Verification Scripts*. It reads them after intake and any pooling on a delegated pass, and after **Review Focus** on the inline pass. Immediately before and immediately after the checks read, read the PR with `gh pr view <n> --json state,headRefOid`. When either read fails, finds a `state` other than `OPEN`, or finds a `headRefOid` other than the reviewed head, discard the checks. The review then continues at the reviewed head with CI unknown. A failed checks read also leaves CI unknown under that section. Once both reads return `OPEN` at the reviewed head, the session adds the Major findings that section makes to the findings the pass holds. Those findings then take **Capture evidence**, **Prepare finding wording**, and settlement like any other finding.

**Capture evidence.** Apply `./references/engineering/review-evidence.md` §§ *Risk*, *Applicability*, and *Capture* using the change map and affected callers. Run this session-owned phase once after all primary reviewers are collected; `-n` and `-x` do not duplicate it. Observed defects enter the candidate list before wording and settlement; capture gaps remain evidence limitations. Retain the resulting Evidence field for Output or the composite caller.

**Prepare finding wording.** Apply `./references/workflow/user-facing-messages.md` § *Finding entry wording* after capture, before findings leave this pass. Use it on inline findings and any later script or `-x` candidate before session verification and adoption. Preparation runs even when a composite suppresses standalone settlement.

Carry each finding's `Group sources` association through pooling, rewording, filtering, and severity changes. Translate its finding ordinal when the output order changes. Do not reconstruct the association from a shared code location or quote. Keep these source paths outside Findings, including on the inline fallback and in composite phase output.

A composite driving this skill through `./references/workflow/verify-pipeline.md` § *The review phase* runs intake, pooling of the reviewers' returns and of the `-x` probes, **Read the PR's checks** on the PR form, evidence capture, the `Pre-existing` label spot-check, and wording preparation, then defers adoption, anchor spot-checks, and verdicts to its verify phase; any other composite runs the settle in full. The PR-form check findings join the set the review phase holds and forwards to triage. The `-x` probes' novel candidates reach the verify phase pooled, one per distinct claim. The `-d` draft is Output's and is forwarded unchanged. <!-- cold -->

**Blocked output.** When `./references/workflow/reviewer-contract.md` § *Safety blocks* makes the primary review terminally blocked, stop with `Review pass: blocked (completed 0/<requested>; reviewer <i> safety blocked: <error>; …)`, every unavailable reviewer's reason included. That line, and with `-x` the `Cross-check:` line (`unattached (<n> findings; primary pass blocked)` or `skipped (<reason>)`, never adopted as the pass), is the whole output: no Summary, Findings, **Reviewed** provenance, or Handoff, since an empty Findings list would be publishable as a clean review.
With `-x` above one probe, the `Cross-check:` line takes its coverage form from `./references/workflow/probe-cross-check.md`. <!-- cold -->

**Inline fallback.** Where the user explicitly asked for an in-session pass, the reviewer cannot launch, or a launched one failed (the reasons `./references/workflow/reviewer-contract.md` § *Degrade rule* closes), announce which it was and run the pass in-session, recording the reason on the `Review pass:` line. Only the runner changes. On a detected fork PR (`./references/engineering/review.md` § *Verification Scripts*), the session loads AGENTS.md and CLAUDE.md only from the merge-base. It applies the `instruction files` rule in `./references/workflow/reviewer-contract.md` § *Launch packet*.

With `-g`, perform the packet's group reads and retain the `Group sources` map under that contract, as a reviewer would.

Build the change map:

- Get the full diff against the base; exclude generated files (lockfiles, build artifacts, snapshots) unless manually edited.
- Group changes by intent: new feature, bug fix, refactor, configuration, tests.
- For each modified export or shared component, search all usages to understand blast radius.
- If the diff exceeds ~1000 non-generated lines and is not one cohesive change, the first finding is "split this PR".
- If the diff bundles refactoring with feature work or bug fixes, flag "separate the refactor", except refactors required to enable the feature.
- On a `paths` object the map is the reviewed files grouped by concern, with the blast-radius search unchanged; the two split findings do not arise.

Read the links Setup extracted:

- Fetch every extracted link concurrently (WebFetch, `gh issue view` / `gh pr view`), or one native probe batching the retrieval per `./references/workflow/agent-fanout.md`, and merge what comes back into the review context. <!-- cold -->
- Record a link that cannot be accessed under **Inaccessible context** with the URL and reason. Do not fabricate what is behind it.

Launch verification scripts per `./references/engineering/review.md` § *Verification Scripts*, always, unless the caller substitutes its own evidence, the PR form's checks stand in for them, or a Setup PR lookup returned a fork PR (`isCrossRepository` true, any state): as soon as the reviewed set is determined, start them over it and review while they run; failures and warnings land as findings before output. `./references/workflow/agent-fanout.md` fixes the route a candidate raised there settles by. <!-- cold -->

Then apply **Review Focus** below, take **Read the PR's checks** on the PR form, then **Capture evidence** and **Prepare finding wording**, and render the output.

## Review Focus

Applied by the reviewer on a delegated pass and by the session on the inline fallback.

**On a `pr` object, examine tests first.** Test diffs reveal intent and expected behavior; read them before the implementation.

**On a `paths` object, read the tests for the behavior they intend** rather than examining them first: no diff dates them. Spend the effort on the exports the rest of the project consumes, then the security surfaces, then the complexity and dead code that collect where nothing has changed in a while.
