# Agent Fan-Out: Probes

How a skill delegates read-only work to other agents as **probes** — self-contained questions whose answers come back as text evidence. **This file is the single source of truth for probe behavior: the probe contract every engine runs under, and the merge contract every answer comes back under.** Engine commands live in `./probe-engines.md` (native) and `./probe-engines-cross-vendor.md` (the `-x` engines), the `-x` cross-check in `./probe-cross-check.md`, and each probe prompt shape in its own `./probe-shape-*.md`. Write mode is not here: executor behavior lives in `./executor-contract.md`, and the write-mode consumer registry and engine registry in `./executor-routing.md`, with the coordinator-side parallel-batch mechanics in `./parallel-batch.md` and the write-mode posture — delegation standing, with its three exceptions — in `./write-mode-posture.md`. Delegated review is not here either: a reviewer reads and runs the review's own verification without writing anything, so it is not a probe, and its contract is `./reviewer-contract.md` — everything about it but the pooling of its returns, which the merge contract below owns for reviewer and probe candidates alike.

## What a probe is

A **probe** is one self-contained, read-only question posed to a separate agent, whose answer comes back as text evidence. Its defining property is **independence**: the probe sees only what its prompt carries — no session context, no accumulated assumptions, no stake in the answer.

## Probe contract (every engine)

- **Self-contained prompt.** Paste in everything the probe must judge — the claims under check, the diff scope or doc paths, absolute paths to the artifacts. Never assume the probe can see the session.
- **One concern per probe.** A claim *list* for one check is one probe (one prompt, one merged answer) — don't fan a per-claim probe swarm when a batched prompt does the job.
- **Read-only, promised always, enforced where the engine can.** Probes verify by reading — files, diffs, docs — never by mutating, and never by running the project's build or suite (a probe stays analysis-only even where its invoking review runs verification scripts itself). Never pass an engine's sandbox-bypass flags. Enforcement varies by engine — see the registry; the promise does not.
- **Demand cited verdicts.** The prompt must require evidence with an artifact-appropriate locator — `file:line` for file-backed claims, a stable source or record locator for external facts. A shape whose verdict is that no evidence bears may instead require the sources and locations searched; an absence cannot cite the line it did not find. An uncited probe answer is an opinion, not evidence.
- **Evidence, not authority.** A probe's answer is weighed, spot-checked where surprising, and can force re-verification — but it never assigns a verdict or overrides the session's own pass. The invoking skill owns its verdicts.
- **Degrade gracefully.** A missing engine, a failed login, or a probe that has died is reported (`Cross-check: skipped (<reason>)`) and the skill proceeds on its own pass. A probe never blocks a skill — but slowness alone is not failure: a probe has no fixed time budget, and one still making progress is waited on and reported at the cadence `./delegated-waiting.md` § *How to wait* fixes; skipping it is the user's call, not a timeout's.
- **Content leaves the machine.** A probe ships its prompt to the engine's vendor. Run a cross-vendor probe only on work the user already uses that vendor's CLI on; when in doubt, ask first.
- **Scratch, not record.** Probe output lands in the host's scratch/temp area — never in the task folder; result files record the *merged outcome*, not probe transcripts.

Engine commands and launch recipes live in `./probe-engines.md` (native; the `-x` engines in `./probe-engines-cross-vendor.md`), the `-x` cross-check contract in `./probe-cross-check.md`, and each probe prompt shape in its own `./probe-shape-*.md` — read the engine registry and the one shape a probe uses when launching it; the probe contract above and the merge contract below govern every engine and every shape.

## Merge contract

The invoking skill compares the probe's answer against its own pass:

- **Agreement** strengthens the evidence — cite it and move on.
- **Contradiction is never silently dropped.** Where the probe contradicts the session's grounding or the artifact's own claims, re-check that spot before assigning the verdict; a confirmed contradiction becomes a finding (in `review-task`, a `CONTRADICTED` claim is evidence toward `conflicts with what exists` / `infeasible as stated`; a `NOT FOUND` on a load-bearing reference is a gap).
- **Novel probe findings are candidates, not findings.** Verify each against the artifact before adopting it into the output — under the session's own severity calibration; never paste a probe finding unverified. A reproducible failure mode is settled by its reproduction rather than a verifier's read — when the domain is code, the bar for what reproduces and how belongs to `../engineering/review.md` § *Verification Scripts*, not here.
- **Pool candidates by location before adopting any.** Where more than one reviewer or probe contributed candidates — `review-code`'s `-n N` puts a fleet of reviewers on one object whenever N is above 1 — group them by where they point — `file:line`, the function or block they land in — so corroboration and contradiction at one spot surface together ahead of the per-candidate verification above. **A location group holds as many candidates as it has distinct claims**: grouping is by location, but deduping is by *semantic equivalence*, so two returns describing the same defect at one spot merge into one candidate while two different defects in one function stay two. Collapsing a group to a single candidate would drop the second defect unverified and mark the first corroborated by a return that never made its claim — a location is where candidates meet, not what makes them the same. Then, for each function a pooled candidate lands in, walk that function's other branches in the session's own read, not a new probe: a probe that found one branch of a two-branch defect leaves the sibling unreported.
- **The outcome line closes the loop.** For the `-x` shapes, the `Cross-check:` line states `clean`, `merged: …`, or `skipped (<reason>)` — the record makes a skipped or empty probe visible instead of leaving absence ambiguous. The verify shape closes on its consuming skill's mandatory **Verified** line instead, which carries the same guarantee for the same reason; `Cross-check:` stays reserved for the `-x` pass, so a composite running both keeps two distinct records. The options-research shape closes on its consumer's `Question research:` line for the same reason, but conditionally rather than mandatorily: the line renders whenever the review surfaced candidate questions and is absent when it surfaced none, that absence being its own unambiguous record (per `./probe-shape-options-research.md`).
