# Reconciliation: Docs → Reality

The direction `resume-task-reconcile` and `review-task-reconcile` write in. It runs on the shared mechanics in `./reconciliation.md` — consent model, who runs the reference sweep, record and annotation formats, `plan.md` openings, run sequence — which this file does not restate.

Findings come from a printed report comparing the docs against reality on disk, so this direction's repairs only ever *weaken* claims the docs overstate; an advance is possible only through the shared verify-and-write engine (§ *Repairs weaken; advances go through the shared engine*). Each composite adds the reference sweep (`./reconciliation-sweep.md`), which its reporting phase does not run.

## Write surface

Exactly four task files, and nothing else:

- `plan.md` — the five shared openings under this direction's constraints: a drift finding clears a checkbox and moves `**Status:**` downward; a box is checked, or a `**Status:**` advanced, only through the shared engine (§ *Repairs weaken; advances go through the shared engine*).
- `result.md` — append-only, except the `## Current state` block, rewritten in place (`./reconciliation.md` § *Current state refresh*); record format in that file's § *The record*. A finalizing advance additionally writes the `## Acceptance` or `**In review:**` section that advance owes (the *Verified advances would close the plan* row, on the resume path).
- `CONTEXT.md` — minimal annotations inside `## References` and `## Open Questions` only, per the carve-out in `./task-lifecycle.md`. Never the `**Status:**` origin marker, never prose rewrites.
- `observations.md` — rewritten wholesale by the sweep: the check's own record, not an edit a finding evidences.

`diagram.md` and a doc task's **deliverable** are outside this surface entirely, on the shared exclusion in `./reconciliation.md` § *Authored surfaces are never written*; drift in either is flagged, never repaired (shared repairs below). The deliverable's `**Published:**` line is the user's to flip or re-date: the sweep reads it, the never-annotated rule routes what it finds, nothing here writes it.

`goals.md` and the upstream `ticket.md` are **never** edited: they are the user's contract. A goal needing a rewrite gets its suggested text printed for the user to apply; a changed *ask* is surfaced for the user to update the ticket. An engineer answer still goes to the user as text, not into the file. Beyond the re-verification an advance owes the shared engine (§ *Repairs weaken; advances go through the shared engine*), this direction never re-runs the acceptance gate and never executes plan work.

## Repairs weaken; advances go through the shared engine

Every **repair** in this direction moves downward: uncheck `- [x]` → `- [ ]`, flip `done → executing` or `in-review → executing`, revert `executing → to-do`. A repair never sets `skipped`, `blocked`, or `in-review`.

An upward move is never a repair, and never this direction's to invent: a box checked, a goal recorded `met`, a status flipped forward — each goes through `./reconciliation.md` § *Strengthen only on verified evidence*, re-verified in the current run, never on a report's claim alone. That holds **even with an engineer's answer**: "yes, that step was done" is not evidence — the engine's re-verification is. Engineer answers refine plan *content*; they never advance *state* on their own.

## Shared repairs (both composites)

Both composites apply these; only the evidence source differs (the resume brief's drift check, the review's cross-file consistency check, and — for the reference row — either pipeline's sweep). Route values are `./reconciliation.md` § *The mapping legend*.

- **Unbacked `- [x]` step** — the shipped claim vanished (file gone, symbol removed, change reverted), or no result section backs the box — **auto**: flip it to `- [ ]` and drop its trailing `([result](…))` link; pending steps carry none, the record stays in `result.md`, and the Reconciliation entry cites the dropped anchor so it stays traceable. Never rewrite the step's **What**/**Verify**; never renumber.
- **Lifecycle repairs** — **auto**, always downward to the weaker claim. Never fabricate an `## Acceptance` section — only a run that has actually run the gate writes one (the *Verified advances would close the plan* row, on the resume path) — or an invented cause, and never flip upward: those are flag only.
  - plan `done`, result with no `## Acceptance` → flip the plan `done → executing` and remove the result's closing `**Completed:**` line (header metadata, not narrative; `implement-task` re-adds it on re-finalize);
  - plan `executing`, no `result.md` → with checked steps or drift-verified shipped work, create a skeleton `result.md` (`implement-task`'s init header) holding the Reconciliation section and point the plan's `**Result:**` line at it; with zero evidence, flip `executing → to-do`, revert `**Result:**` to the pre-execution placeholder, create nothing; **ask** when the evidence is ambiguous (partial artifacts that may or may not be this task's work);
  - plan `blocked` or `in-review`, no `result.md` → **flag only**: the section that state owes names a cause or pending goal that can't be invented;
  - plan `done`, no `result.md` → flip `done → executing` (nothing records the gate having run), then apply the no-`result.md` rule above;
  - a plan status outside the vocabulary registered in `./task-lifecycle.md` → **ask**; the intended state can't be inferred.
- **Result records work the plan doesn't show** (result section exists, plan still `- [ ]`) — the record *nominates*; checking the box goes through the shared engine like any other advance (§ *Repairs weaken; advances go through the shared engine*). A run that re-verifies the step checks it; a run that doesn't leaves it flag only, naming `implement-task` (or the user) to confirm and flip.
- **`diagram.md` no longer matches reality** (the report's drift check nominates) — **flag only** per `./reconciliation.md` § *Authored surfaces are never written*, which fixes what to name and that nothing is written, with the finalization stop the standing divergence triggers in that file's § *Strengthen only on verified evidence*.
- **Cited reference materially changed or gone** — governed in full by `./reconciliation.md` § *Cited reference changed*, of whose two deltas this direction takes the **docs → reality** one: a changed reference contradicting `CONTEXT.md` prose is **flag only** here, that prose never being rewritten in this direction.
- **Never-annotated surface changed or broken** — the trigger and the rule are `./reconciliation.md` § *Never-annotated surfaces*, which governs while this row adds nothing, none of the three surfaces being in this write surface: on a `warn`, name the changed page and the claim it leaves stale (for a pause section, that the cause it names may no longer hold); on a `block`, name the page as gone.

## `resume-task-reconcile` — brief findings

Findings come from the brief's sections (Drift since plan, Commits since watermark, Open questions) and from this phase's own sweep — the brief itself sweeps nothing, and leaves every watermark write to this phase (`./reconciliation-commits.md` § *Read/write split*). Broken links and reference-answered questions use `./reconciliation.md` § *Annotation formats*; unbacked steps and lifecycle states use the shared repairs above; route values are that file's § *The mapping legend*. The rest:

- **A `met` goal no longer holds** — **auto**: no checkbox change by itself; flip the plan `done → executing` (or `in-review → executing` when the regressed goal backs an in-review task), dropping the result's closing `**Completed:**` line where one exists; the Reconciliation entry names the regressed `G<n>` and supersedes the prior `## Acceptance`; "Not reconciled" names `implement-task`.
- **Commit-nominated candidate** (a "Commits since watermark" line nominating a pending step) — **verify**: re-run that step's `**Verify:**` as its full unit-outcome tier (`./execution-loop.md` § *Two verification tiers*), the commit itself — a revert included — attesting nothing. Passes → check `- [x]`, its trailing `([result](…))` link pointing at this run's own `## Reconciliation` entry, which records the advance; `./reconciliation-commits.md` § *The record* fixes that anchor, and `./reconciliation.md` § *The record* the same-day ` (2)` suffix behind it. Fails, or the criterion cannot re-run in this run (narrative wording, a session-only artifact) → surface with the box left `- [ ]`; "Not reconciled" names `implement-task`, or the reason the criterion isn't re-runnable.
- **Verified advances would close the plan** (this run's re-verification leaves no pending step and no unmet goal bar `(external)` ones) — **verify**: finalizing is the shared engine's, never this section's. `executing → done`, or `executing → in-review` on an `(external)`-only remainder, owes the full goal gate over every goal, fresh current-run integrated health, and the diagram stop — all three of `./reconciliation.md` § *Strengthen only on verified evidence*. Any one unmet → the run stays `executing` and surfaces what held it; "Not reconciled" names `implement-task`. Where all three hold, record the gate's per-goal verdicts in a `## Acceptance` section on `result.md`, and on the `in-review` branch the `**In review:**` section `./task-lifecycle.md` requires; without them the next run's *Lifecycle repairs* row flips this advance straight back and strips the `**Completed:**` line it wrote.
- **`[info]` findings** (pending artifact already exists, adjacent refactor, auth-walled link, a commit touching only checked steps' paths) — no edit; info stays info: an observation is not the engine's re-verification, so on its own it checks no box and notes no completion.
- **Watermark writes** (the scan's own bookkeeping, not a finding an edit answers) — **auto**: mechanical and evidence-backed. A missing baseline is seeded at `<ref>`'s current tip and the seed reported, once a `result.md` exists to hold the entry; an orphaned entry is re-seeded at that same tip and the re-seed recorded (`./reconciliation-commits.md` § *Degenerate cases*); a scan that ran writes its dated commit list onto the Reconciliation entry's `**Commits:**` line and advances the `**Pointers:**` entry to that scanned tip in the Current state refresh (same file § *The record*). Every one of those writes is owed an entry to record it, and none happens without one (same file § *The record*: the advance and the record are one act). Those sections fix the list's cap and every format; this row adds none of its own.
- **External blocker cleared** (PR merged, ticket closed) — the `blocked`-clearing case of `./reconciliation.md` § *Cited reference changed*: **apply that section in full**, its `**Pointers:**` refresh and its no-status-flip rule included, and **route by the surface the blocker is cited from** per its per-occurrence rule — a `**Pointers:**` entry takes the auto refresh; a URL cited only from the active pause section is **flag only** under the never-annotated rule, naming the cleared cause and writing nothing into the section. "Not reconciled" names `implement-task` either way.
- **Missing `goals.md` / missing `CONTEXT.md`** — cannot be fabricated; stays flagged, next skill `plan-task`.

## `review-task-reconcile` — assessment findings

Findings come from the assessment's sections and from this phase's own sweep — `review-task` sweeps nothing either; its reference findings take `./reconciliation.md` § *Annotation formats*, as on the resume side. Cross-file drift findings use the shared repairs above.

Most of this review's findings need the engineer — that is what the assessment's Questions section is for. Under this composite they are not left rhetorical: put the section's **numbered open questions** to the engineer as one batched round, the concrete options already attached, and write the answers into the plan exactly as given, with no redesign around them. The section's **Answered by research** list is not part of that standalone question round: its entries are evidence, not mapping targets. Dispatch each originating finding through the rows below. Where research disproved the finding, nothing remains to route; where it supplied missing content but the artifact is still defective, the finding remains and its existing **ask** row presents that answer as the concrete proposed edit for the engineer to accept. The ask decides whether to write the repair; it does not ask the settled question again. The rest:

- **Scope partition not total** (a goal ID neither delivered nor deferred) — **ask**: deliver it, defer it, or drop the goal (dropping means the user edits `goals.md`); apply the chosen partition to the plan's `## Scope`.
- **Stale or orphan goal citations** (a step cites a goal ID absent from `goals.md`; a non-infra step cites nothing) — **ask**: point the citation at the right goal, mark the step `none (infra/refactor)`, or remove the step; apply the answer.
- **Vague or untestable Verify criterion** — **ask**, offering the concrete rewrite the assessment suggested; apply the accepted wording to the step's `**Verify:**` line.
- **Gaps and needs-clarification steps** — **ask** the targeted question from the Questions section; fold the answer into the step's **What**/**Verify** (or the plan's Scope).
- **Goal quality findings** (`weak` / `vague-or-untestable` / `unresolved`) — never edited: `goals.md` is the user's contract. Print the suggested rewrite for the user to apply; an engineer answer here still goes to the user as text.
- **CONTEXT ↔ goals / CONTEXT ↔ plan contradictions** — **ask** which side is right, applying the resolution only where the write surface allows: the plan's Scope/steps, or an annotation in CONTEXT's `## Open Questions` recording the ruling. CONTEXT prose (MVP scope, "Not Doing", Recommended Direction) is never rewritten — a ruling that changes direction is re-planning; name `plan-task`.
- **Restated grounding** (the same decision, finding, or question maintained in both `CONTEXT.md` and `plan.md`) — **ask**: confirm the fact's home (`./one-home.md` § *One home per fact* — grounding's home is `CONTEXT.md`) and whether the copies still agree, then collapse the restated content on the **plan side** to a citation of the home section, preserving any plan-time deltas interleaved with it. Never auto-applied: separating restatement from delta and choosing the surviving copy is interpretive, and diverged copies are a contradiction to rule on first (the row above). The CONTEXT side is never rewritten here; if the plan copy carries newer content that should become the grounding, that's a `reconcile-task` (session → docs) or `plan-task` job.
- **Infeasible or conflicts-with-existing steps** — flag only: fixing them is redesign, out of scope even here; name `plan-task`.
