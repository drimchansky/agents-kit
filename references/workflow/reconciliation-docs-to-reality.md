# Reconciliation: Docs → Reality

The direction `resume-task-reconcile` and `review-task-reconcile` write in. It runs on the shared mechanics in `./reconciliation.md` — consent model, who runs the reference sweep, record and annotation formats, `plan.md` openings, run sequence, § *Grounding docs change on evidence, never silently*, and § *The upstream ask is writable, and never rewritten quietly* — which this file does not restate.

Findings come from a printed report comparing the docs against reality on disk, so this direction's repairs only ever *weaken* claims the docs overstate; an advance is possible only through the shared verify-and-write engine (§ *Repairs weaken; advances go through the shared engine*). Grounding content — `goals.md`, `CONTEXT.md` prose — is a **judged** edit, under the same shared rule the session direction runs on (`./reconciliation.md` § *Grounding docs change on evidence, never silently*). Each composite adds the reference sweep (`./reconciliation-sweep.md`), which its reporting phase does not run.

## Write surface

Five task files, plus the two surfaces reaching past the folder:

- `plan.md` — the five shared openings under this direction's constraints: a drift finding clears a checkbox and moves `**Status:**` downward; a box is checked, or a `**Status:**` advanced, only through the shared engine (§ *Repairs weaken; advances go through the shared engine*).
- `result.md` — append-only, except the `## Current state` block, rewritten in place (`./reconciliation.md` § *Current state refresh*); record format in that file's § *The record*. A finalizing advance additionally writes the `## Acceptance` or `**In review:**` section that advance owes (the *Verified advances would close the plan* row, on the resume path).
- `CONTEXT.md` — **auto** for minimal annotations inside `## References` and `## Open Questions`, per the carve-out in `./task-lifecycle.md`; a prose section as a **judged** edit (`./reconciliation.md` § *Grounding docs change on evidence, never silently*).
- `goals.md` — **judged**, per that same section and the durable-ID scheme it cites: a goal reworded, added, or retired on the report's evidence, the rewrite it declined recorded beside the one it wrote. Only § *`review-task-reconcile` — assessment findings* nominates such an edit; the brief side has no row that writes it.
- `observations.md` — rewritten wholesale by the sweep: the check's own record, not an edit a finding evidences.
- `ticket.md` and every applicable `GROUP_CONTEXT.md` — **judged**, on the added terms of `./reconciliation.md` § *The upstream ask is writable, and never rewritten quietly*. This direction reads reality against the docs, which makes its ticket edits the narrowest kind: a citation the sweep found broken, or an ask the fetched source shows has moved. A ticket rewritten toward what the disk turned out to contain is exactly the laundering that section forbids — that finding is *Needs work* naming `plan-task`.

A doc task's **deliverable** is outside this surface entirely, on the shared exclusion in `./reconciliation.md` § *Authored surfaces are never written*; drift in it is flagged, never repaired (shared repairs below). The deliverable's `**Published:**` line is the user's to flip or re-date: the sweep reads it, the never-annotated rule routes what it finds, nothing here writes it.

Beyond the re-verification an advance owes the shared engine (§ *Repairs weaken; advances go through the shared engine*), this direction never re-runs the acceptance gate and never executes plan work.

## Repairs weaken; advances go through the shared engine

Every **repair** in this direction moves downward: uncheck `- [x]` → `- [ ]`, flip `done → executing` or `in-review → executing`, revert `executing → to-do`. A repair never sets `skipped`, `blocked`, or `in-review`.

An upward move is never a repair, and never this direction's to invent: a box checked, a goal recorded `met`, a status flipped forward — each goes through `./reconciliation.md` § *Strengthen only on verified evidence*, re-verified in the current run, never on a report's claim alone. **A judged edit buys no advance.** Rewriting a step's `**Verify:**` line does not verify the step, and rewording a goal does not meet it: judged edits move *content*, the engine alone moves *state*, and a run that lets the first stand in for the second has graded its own paper (`./reconciliation.md` § *Grounding docs change on evidence, never silently*). The same holds for anything the engineer says in passing: "yes, that step was done" is not evidence — the engine's re-verification is.

## Shared repairs (both composites)

Both composites apply these; only the evidence source differs (the resume brief's drift check, the review's cross-file consistency check, and — for the reference row — either pipeline's sweep). Route values are `./reconciliation.md` § *The mapping legend*.

- **Unbacked `- [x]` step** — the shipped claim vanished (file gone, symbol removed, change reverted), or no result section backs the box — **auto**: flip it to `- [ ]` and drop its trailing `([result](…))` link; pending steps carry none, the record stays in `result.md`, and the Reconciliation entry cites the dropped anchor so it stays traceable. Never rewrite the step's **What**/**Verify**; never renumber.
- **Lifecycle repairs** — **auto**, always downward to the weaker claim. Never fabricate an `## Acceptance` section — only a run that has actually run the gate writes one (the *Verified advances would close the plan* row, on the resume path) — or an invented cause, and never flip upward: those are flag only.
  - plan `done`, result with no `## Acceptance` → flip the plan `done → executing` and remove the result's closing `**Completed:**` line (header metadata, not narrative; `implement-task` re-adds it on re-finalize);
  - plan `executing`, no `result.md` → with checked steps or drift-verified shipped work, create a skeleton `result.md` (`implement-task`'s init header) holding the Reconciliation section and point the plan's `**Result:**` line at it; with zero evidence, flip `executing → to-do`, revert `**Result:**` to the pre-execution placeholder, create nothing; **judged** when the evidence is ambiguous (partial artifacts that may or may not be this task's work), and ambiguity resolves *downward* — the weaker claim is the one a repair may make without the engine;
  - plan `blocked` or `in-review`, no `result.md` → **flag only**: the section that state owes names a cause or pending goal that can't be invented;
  - plan `done`, no `result.md` → flip `done → executing` (nothing records the gate having run), then apply the no-`result.md` rule above;
  - a plan status outside the vocabulary registered in `./task-lifecycle.md` → **judged**, and downward like every other repair here: set the weakest registered status the folder's own evidence supports, and record the unrecognized value verbatim so nothing about the original is lost.
- **Result records work the plan doesn't show** (result section exists, plan still `- [ ]`) — the record *nominates*; checking the box goes through the shared engine like any other advance (§ *Repairs weaken; advances go through the shared engine*). A run that re-verifies the step checks it; a run that doesn't leaves it flag only — *Needs work*, naming `implement-task` to re-verify and flip.
- **Inherited group constraint contradicts a task artifact** — nominated by the brief's drift finding weighing the current chain against a pending step, or by the assessment's `group context ↔ …` Cross-File Drift pair; either way **judged**, on both surfaces. Rule on which side the evidence holds, then write it: the group file itself per `./reconciliation.md` § *The upstream ask is writable, and never rewritten quietly*, and the task-local consequence to the step's **What**/**Verify**, the `CONTEXT.md` prose section, or the `goals.md` line that owns it — the last two per `./reconciliation.md` § *Grounding docs change on evidence, never silently*. A group file governs siblings this run never opened, so where the evidence does not clearly favour one side, the task-local surface is the one that yields. Nothing advances on the contradiction, and a ruling leaving the plan to redesign is *Needs work* naming `plan-task`.
- **Cited reference materially changed or gone** — governed in full by `./reconciliation.md` § *Cited reference changed*.
- **Never-annotated surface changed or broken** — the trigger and the rule are `./reconciliation.md` § *Never-annotated surfaces*, which governs while this row adds nothing, neither surface being in this write surface: on a `warn`, name the changed page and the claim it leaves stale (for a pause section, that the cause it names may no longer hold); on a `block`, name the page as gone.

## `resume-task-reconcile` — brief findings

Findings come from the brief's sections (Drift since plan, Commits since watermark, Open questions) and from this phase's own sweep — the brief itself sweeps nothing, and leaves every watermark write to this phase (`./reconciliation-commits.md` § *Read/write split*). Broken links and reference-answered questions use `./reconciliation.md` § *Annotation formats*; unbacked steps and lifecycle states use the shared repairs above; route values are that file's § *The mapping legend*. The rest:

- **A `met` goal no longer holds** — **auto**: no checkbox change by itself; flip the plan `done → executing` (or `in-review → executing` when the regressed goal backs an in-review task), dropping the result's closing `**Completed:**` line where one exists; the Reconciliation entry names the regressed `G<n>` and supersedes the prior `## Acceptance`; "Not reconciled" names `implement-task`.
- **Commit-nominated candidate** (a "Commits since watermark" line nominating a pending step) — **verify**: re-run that step's `**Verify:**` as its full unit-outcome tier (`./execution-loop.md` § *Two verification tiers*), the commit itself — a revert included — attesting nothing. Passes → check `- [x]`, its trailing `([result](…))` link pointing at this run's own `## Reconciliation` entry, which records the advance; `./reconciliation-commits.md` § *The record* fixes that anchor, and `./reconciliation.md` § *The record* the same-day ` (2)` suffix behind it. Fails, or the criterion cannot re-run in this run (narrative wording, a session-only artifact) → surface with the box left `- [ ]`; "Not reconciled" names `implement-task`, with the reason where the criterion isn't re-runnable.
- **Verified advances would close the plan** (this run's re-verification leaves no pending step and no unmet goal bar `(external)` ones) — **verify**: finalizing is the shared engine's, never this section's. `executing → done`, or `executing → in-review` on an `(external)`-only remainder, owes the full goal gate over every goal and fresh current-run integrated health — both of `./reconciliation.md` § *Strengthen only on verified evidence*. Either one unmet → the run stays `executing` and surfaces what held it; "Not reconciled" names `implement-task`. Where both hold, record the gate's per-goal verdicts in a `## Acceptance` section on `result.md`, and on the `in-review` branch the `**In review:**` section `./task-lifecycle.md` requires; without them the next run's *Lifecycle repairs* row flips this advance straight back and strips the `**Completed:**` line it wrote.
- **`[info]` findings** (pending artifact already exists, adjacent refactor, auth-walled link, a commit touching only checked steps' paths) — no edit; info stays info: an observation is not the engine's re-verification, so on its own it checks no box and notes no completion.
- **Watermark writes** (the scan's own bookkeeping, not a finding an edit answers) — **auto**: mechanical and evidence-backed. A missing baseline is seeded at `<ref>`'s current tip and the seed reported, once a `result.md` exists to hold the entry; an orphaned entry is re-seeded at that same tip and the re-seed recorded (`./reconciliation-commits.md` § *Degenerate cases*); a scan that ran writes its dated commit list onto the Reconciliation entry's `**Commits:**` line and advances the `**Pointers:**` entry to that scanned tip in the Current state refresh (same file § *The record*). Every one of those writes is owed an entry to record it, and none happens without one (same file § *The record*: the advance and the record are one act). Those sections fix the list's cap and every format; this row adds none of its own.
- **External blocker cleared** (PR merged, ticket closed) — the `blocked`-clearing case of `./reconciliation.md` § *Cited reference changed*: **apply that section in full**, its `**Pointers:**` refresh and its no-status-flip rule included, and **route by the surface the blocker is cited from** per its per-occurrence rule — a `**Pointers:**` entry takes the auto refresh; a URL cited only from the active pause section is **flag only** under the never-annotated rule, naming the cleared cause and writing nothing into the section. "Not reconciled" names `implement-task` either way.
- **Missing `goals.md` / missing `CONTEXT.md`** — cannot be fabricated; stays flagged, next skill `plan-task`.

## `review-task-reconcile` — assessment findings

Findings come from the assessment's sections and from this phase's own sweep — `review-task` sweeps nothing either; its reference findings take `./reconciliation.md` § *Annotation formats*, as on the resume side. Cross-file drift findings use the shared repairs above.

Most of this review's findings turn on a choice — that is what the assessment's Questions section is for. Under this composite those questions are neither left rhetorical nor put to the engineer: the run **answers them itself** and writes the answer into the home file each row below names. Each numbered question already carries concrete options, so the ruling is a choice among them on the assessment's own evidence, recorded with the option declined (`./reconciliation.md` § *Consent model: findings apply, the record carries them*) — never a redesign past what the finding reached. The section's **Answered by research** list is not a set of questions to rule on: its entries are evidence. Dispatch each originating finding through the rows below. Where research disproved the finding, nothing remains to route; where it supplied missing content but the artifact is still defective, the finding remains and its row writes that answer as the repair. The rest:

- **Scope partition not total** (a goal ID neither delivered nor deferred) — **judged**: deliver it, defer it, or retire the goal, deciding on what the plan's own steps already reach — a goal some step delivers is delivered, one no step touches is deferred, and retirement needs the ticket or CONTEXT to have dropped the requirement outright. A retirement is written to `goals.md` per `./reconciliation.md` § *Grounding docs change on evidence, never silently*, its ID never reused, and every step citing the retired ID goes through the *Stale or orphan goal citations* row; apply the chosen partition to the plan's `## Scope`.
- **Ticket criterion maps to no goal** (`ticket ↔ goals` drift) — **judged**: add a delivering goal, written to `goals.md` per `./reconciliation.md` § *Grounding docs change on evidence, never silently* and taking the next free `G<n>`. Dropping the criterion from `ticket.md` instead is the narrower ticket edit § *Write surface* describes, and it needs evidence the ask itself moved — the criterion being unimplemented is not that evidence.
- **Stale or orphan goal citations** (a step cites a goal ID absent from `goals.md`; a non-infra step cites nothing) — **judged**: point the citation at the right goal where one obviously fits, mark the step `none (infra/refactor)` where it delivers no goal, or add the missing goal — the addition written to `goals.md` per `./reconciliation.md` § *Grounding docs change on evidence, never silently*, taking the next free `G<n>` and the step's citation repointed at it. Removing the step is redesign: that one is *Needs work* naming `plan-task`.
- **Vague or untestable Verify criterion** — **judged**: apply the concrete rewrite the assessment suggested to the step's `**Verify:**` line. A criterion rewritten this run does not thereby pass — the box moves only through the engine (§ *Repairs weaken; advances go through the shared engine*).
- **Gaps and needs-clarification steps** — **judged**: fold the assessment's own answer into the step's **What**/**Verify** (or the plan's Scope), within the finding's scope.
- **Goal quality findings** (`weak` / `vague-or-untestable` / `unresolved`) — **judged**: write the assessment's suggested rewrite into `goals.md` per `./reconciliation.md` § *Grounding docs change on evidence, never silently* (an `unresolved` goal's resolution included), an `_(unresolved: …)_` marker dropping with it. Where the assessment suggested no rewrite, there is nothing to choose among: that one is *Needs work* naming `plan-task`.
- **CONTEXT ↔ goals / CONTEXT ↔ plan contradictions** — **judged**: rule on which side the evidence supports, then write the ruling where it lands — the plan's Scope/steps, the `goals.md` line, or the CONTEXT prose section (MVP scope, "Not Doing", Recommended Direction), each per `./reconciliation.md` § *Grounding docs change on evidence, never silently* — or an annotation in CONTEXT's `## Open Questions` recording the ruling when no section changes. Prefer the surface with the later evidence behind it, and record the side that lost. A ruling that changes direction still leaves the plan to redesign: write the grounding, and name `plan-task` as *Needs work* for the plan.
- **Restated grounding** (the same decision, finding, or question maintained in both `CONTEXT.md` and `plan.md`) — **judged**: settle the fact's home (`./one-home.md` § *One home per fact* — grounding's home is `CONTEXT.md`) and whether the copies still agree, then collapse the restated content on the **plan side** to a citation of the home section, preserving any plan-time deltas interleaved with it. Never auto: separating restatement from delta and choosing the surviving copy is interpretive, and diverged copies are a contradiction to rule on first (the row above). The CONTEXT side changes only where the plan copy's newer content is the surviving grounding — written per `./reconciliation.md` § *Grounding docs change on evidence, never silently*; otherwise it stays as it was.
- **Infeasible or conflicts-with-existing steps** — flag only: fixing them is redesign, out of scope even here; name `plan-task`.
