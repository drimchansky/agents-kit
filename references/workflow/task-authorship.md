# Task Authorship: The Write-Surface Registry

The per-file authorship and write-surface registry — who creates and mutates each task-folder file, the `## Current state` block contract, and the `## Decision log` rule — split out of `./task-lifecycle.md`, which keeps the status vocabulary and the companion-result-file rule. Read this file when writing any task-folder file.

## Files

- **`ticket.md`** (optional) — the product-facing ask, upstream of the four core artifacts (see `./ticket-format.md`).
  - No `**Status:**` field.
  - Authored by the user or `prepare-ticket`, and freely edited by the user. `refine-idea` and `plan-task` read it and derive `CONTEXT.md` / `goals.md` from it; the lifecycle never mutates it. The reconcilers treat it as read-only too — a changed ask is *Yours to apply*, never written (see `./reconciliation.md`).
- **`CONTEXT.md`** — the task's static grounding context (capitalized).
  - No `**Status:**` field.
  - Created by `refine-idea`, `plan-task`, or `decompose-task`; never mutated after creation, except the reconciliation carve-out registered in `./task-lifecycle.md` § *Status values*: minimal annotations in `## References` / `## Open Questions`, and prose sections rewritten only through a confirmed judgment item (`./reconciliation.md` § *Grounding docs change by confirmation, never silently*).
- **`goals.md`** — the task's goals: the acceptance criteria for what "done" looks like.
  - No `**Status:**` field.
  - Drafted by `plan-task` before the plan, or hand-authored; freely edited by user. A reconciler may add, reword, or retire a goal, only through a confirmed judgment item and the durable-`G<n>` scheme (`./reconciliation.md` § *Grounding docs change by confirmation, never silently*); no other skill authors its content — `maintain`'s format sweep may rename a goal-shaped legacy file onto the role name, but never edits what's inside.
- **`plan.md`** — the contract: scope, steps, verify criteria.
  - `**Status:**` is a **lifecycle state**.
  - Created by `plan-task` (`to-do`); transitioned by `implement-task`; reconciled by the docs → reality composites `resume-task-reconcile` / `review-task-reconcile` and by `reconcile-task` — a reconciler's repairs move state downward, and either direction advances it *upward* only on evidence re-verified in the current run (`./reconciliation.md` § *Strengthen only on verified evidence*).
- **`observations.md`** (optional) — the last observed state of the external references the folder cites from an actionable surface, one dated line per URL (format in `./task-observations.md`; scope in `./reconciliation-sweep.md` § *Scope*).
  - No `**Status:**` field; the dated `_Swept:_` line carries currency instead.
  - Rewritten **wholesale** by every reconciler's reference sweep (`./reconciliation-sweep.md` § *Ledger*); no other skill writes it, and nothing in it is appended. `resume-task` reads it and quotes its dated lines without fetching. Its absence is never drift — no sweep has run, or nothing is cited from an actionable surface.
- **`result.md`** — a rewritable `## Current state` header block above an append-only execution log.
  - No `**Status:**` field; `plan.md` is the task's single lifecycle home, and what each of its states owes this file is the companion invariant in `./task-lifecycle.md` § *Companion result file*.
  - Created by `implement-task`, which appends the execution log and writes the `**Blocked:**`, `**In review:**`, `## Acceptance`, and closing `**Completed:**` sections its plan's state owes. The docs → reality composites append `## Reconciliation` sections, may drop the closing `**Completed:**` line alongside a plan flip out of `done`, and may create a missing result file. `reconcile-task` also appends `## Reconciliation` sections; it and the composites may advance the plan's state on evidence re-verified in the current run (`./reconciliation.md` § *Strengthen only on verified evidence*).
  - The `## Current state` block sits directly under the link header. It is **derived metadata** — the same class as the closing `**Completed:**` line, not narrative: rewritten in place (never appended) by `implement-task`, `reconcile-task`, and the docs → reality composites; ≤1 KB; carrying `_Updated: YYYY-MM-DD_`, a one-line status gloss, `**Pointers:**` (the delivery vehicle's identifiers — branch, PR, SHA, ticket; see `./one-home.md` § *One home per fact*, external-system facts), and `**Next:**`. One `**Pointers:**` entry survives every rewrite: the commit watermark (`./reconciliation-commits.md` § *The watermark*), a scan floor no later run can re-derive, so **every** writer of the field carries it forward — `implement-task` included — and only a reconciler advances it, only where that file says. A regenerable digest: never the sole home of any fact, and it may never assert a stronger lifecycle state than the plan's `**Status:**` header, which its gloss line restates. Expected while the plan is **live** (`executing`/`blocked`/`in-review`); under a `done` plan the block keeps its last rewrite frozen, except `**Pointers:**` and the `_Updated:_` line that dates it, which stay live — external-system state is world-truth, so a reconciler still refreshes it there after the gate has run, re-dating the block to say when (`./reconciliation.md` § *Current state refresh*); a legacy result without one is conformant — create the block at the next write.
  - A result may also carry an optional `## Decision log`: an **append-only** index of dated one-liner pointers to where each decision is actually recorded (a result anchor, a `CONTEXT.md` section, a plan step, or a store-level `DECISIONS.md` entry) — never the decision text itself. Everything below the `## Current state` block is append-only.
