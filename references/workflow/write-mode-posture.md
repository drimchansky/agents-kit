# Write-Mode Posture: When Delegation Pays

The one decision for the write-mode consumers registered in `./executor-contract.md` § *Write-mode routing* — split out of that file, which keeps the consumer registry and the engine defaults. **This file is the single home for _when_ delegation pays, and for the cadence it is decided on.** Every input below is read per unit; what a consumer may pre-state is one term — its packet-cost prior — plus its default posture, and nothing else.

**Take it per unit.** Run the steps below for each unit as it comes up, never once for a run: every step reads *this* unit — what it needs specified, how much of the coordinator's own context it would spend, and where it sits in the run — so a decision taken on the first unit's facts is not this unit's decision, and a run's last unit reads differently from its first.

1. **Can the unit be specified now?** Every fact the executor needs — the unit's text, its criterion, its edit surface — writable into the packet before it runs, with no mid-unit user interaction expected and no next action that depends on the last one's output. **No → inline**, whatever the rest says: a unit whose shape is discovered by running it cannot be handed over before it runs.
2. **Is this unit too small for any packet?** Inline volume — the reading, searching, and iterating a unit would spend in the coordinator's own context — has a usual size for each unit *kind*. Read *this* unit's inline volume against that usual size, not against the packet cost: a unit **far below** its kind's usual size is cheaper to do than to describe, whatever assembling a packet would have cost. **Far below → inline**, whatever step 3 says.
3. **Does the saving compound?** Delegation buys context economy for the units that follow it, so it earns most where units remain: **units remaining → delegate**, and that compounding is what outweighs a packet cost heavier than any single unit's inline volume. On the **last unit** nothing follows to buy economy for, so the consumer's **default posture** decides. A unit in a parallel batch reads the batch's other units as remaining — they run alongside it, and each one's work is context the coordinator does not spend — so no batched unit is the last unit, whichever position its batch holds in the run; that branch is for a unit that runs alone at the run's end.

The registered defaults differ on the **packet-cost prior** alone, not on principle — the cost of assembling a self-contained prompt for one unit of that kind plus reading the evidence report back, which follows from the unit *kind* rather than the unit, so a consumer states it once. Step 3's last-unit branch is where that difference lands, the one place the prior decides anything. A unit that arrives **pre-specified in a durable artifact** is already most of its own packet, so its packet cost is low and its consumer's default is delegation. A unit **framed in session** must have its packet reconstructed from context held nowhere on disk, so its packet cost is high and its consumer's default is inline.
