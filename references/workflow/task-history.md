# Task history

Use the entry in [the history template](../templates/history.md). The dated heading names the topic. Include the question, options considered, choice, basis, and evidence source. Include Was and Now for each rewritten goal, ticket passage, or group line. Name the file and section and preserve both wordings.

The run that settles the decision appends one entry to the task's `history.md` in write order. Before appending, check that entry without following links. A symlink or other non-regular entry gets no append. A `**Status:**` line in its header above the first `##` marks a [documentation deliverable](./doc-task-files.md), which also gets no append. A skill that may not read task history checks only the entry type. When the append is held, also hold each live edit that requires the record, and report both. For a deliverable, report that it needs a rename to an unused task-local Markdown filename, with references to it updated. Otherwise append a blank line and the complete entry with a file append operation that creates the file if absent. A repeated topic or date needs no unique suffix.

Keep the current rule and one-line reason at its [live home](./one-home.md). Leave retained approach comparisons with [the approach owner](./task-approaches.md). Apart from the header check above, read or cite task history only at the user's request.
