# Reconciliation: Verified Findings (`review-pr-triage-verify-reconcile`)

The `review-pr-triage-verify-reconcile` composite's finding-type → edit mapping — the session → docs direction's second member — split out of `./reconciliation-session-to-docs.md`, which keeps the direction's shared rules and the `reconcile-task` mapping. Read this file when running that composite's reconcile phase. Bare `§` citations inside resolve against `./reconciliation.md`, as they did at the section's original home.

## `review-pr-triage-verify-reconcile` — verified findings

Findings come from phase 1 — the `review-pr-triage-verify` run the composite executes whole — and from nowhere else: this phase derives no finding of its own and sweeps nothing, per `./reconciliation.md` § *External reference check*'s exemption for a finding set pinned to a producing phase. Each is taken as that phase left it, its verdict, severity, `file:line`, root cause, and fix options all unchanged.

The legend in `./reconciliation-session-to-docs.md` § *`reconcile-task` — session findings* holds unchanged, and only **ask** appears under it — this phase has no obvious-fix path (`./reconciliation.md` § *Consent model*), so nothing it writes is auto, and it re-verifies no claim, so nothing is verify. Its only writes are the appended steps, the reopen below, and the record: it checks no box, marks no goal, and advances no status.

- **Confirmed finding, accepted in the round** → **ask**: append one `- [ ]` step, built and placed by the rules below.
- **Confirmed finding, declined or unanswered** → no file is written for it; the printed change list's "Not reconciled" names it with the engineer's reason, or `awaiting engineer answer`.
- **Withdrawn, Inconclusive, or Unverified finding** → never offered, so it reaches neither the round nor a file: the verify phase's verdict is the contract, not something a confirmation round may overturn. "Not reconciled" carries that verdict as the reason.
- **Finding triage landed outside open** (its bucket standing in for a verdict) → never offered either, and for a distinct reason: it has no verdict to filter on, and its bucket already says it is handled. "Not reconciled" carries the bucket.

**The round.** One batched round, after phase 1's Output has printed in full — that Output is this run's report, which is what satisfies § *Sequence and output* step 1; the rest of that sequence holds, its sweep step exempt and its obvious-fix step vacuous. Each question asks two things together: accept or decline, and the goal ID(s) the defect threatens. A step is written only where **both** authorities hold — the **Confirmed** verdict *and* the acceptance. (`fix-findings` takes either one on its own; appending a step takes both, because appending is a scope act, which the new-step row in `./reconciliation-session-to-docs.md` § *`reconcile-task` — session findings* already classes as a judgment item.) A finding whose goal the round cannot settle is **declined**, never written with a guessed citation. Nothing is written before the round is answered, and a round that accepts nothing writes no file at all — no entry, no status flip, no `## Current state` rewrite — per § *Sequence and output*'s empty-run rule, whose `observations.md` exception this phase has nothing to fire.

**The produced step.** It takes the plan's own shape — a `### Step Na — <title>` heading, titled for the fix rather than the complaint, over the `- [ ]` line and the field lines `plan-task` § *Output* fixes. Every field derives from the finding and the round's answer, and the step carries no field the plan's other steps don't: provenance is not a step field, because the record below already pairs each step with its finding (`./reconciliation.md` § *One home per fact*).

- **What** — the finding's **targeted** fix option, the first of the options its verdict carries (`verify-issue` orders them targeted → thorough), in one sentence, carrying the finding's `file:line`.
- **Verify** — the criterion `fix-findings` § *Applying Fixes* sets in its **Source** binding, written out against this finding's own root cause and reproduction path. It names only that immediate outcome, never the domain health recipe; the eventual `implement-task` run supplies full health at its declared boundary.
- **Goal** — the goal ID(s) the round settled: the ones the defect threatens, a defect in shipped work threatening the goal that work delivers, and a `**Goal:**` line naming what its step delivers (`./task-goals.md`). A finding against scaffolding takes that file's existing escape, `**Goal:** none (infra/refactor)`; there is no other.
- **Depends on** — `none`, unless two accepted findings share a surface: then the later step names the earlier, so nothing runs them concurrently against one file.
- **Touches** *(optional)* — the chosen fix option's stated blast radius, the derivation `./fix-findings-recovery.md` § *Delegation mechanics*'s **Parallel batches** already uses for a fix's declared surface, rather than the finding's `file:line` anchor alone.

**Where the steps land.** At the end of `## Steps`, after the last existing step and anything following it, as `Step Na`, `Nb`, … on the last existing step number `N` — the step-stability rule in `./reconciliation.md` § *The `plan.md` write surface* — so no existing number moves and every `#step-<n>--<slug>` anchor a prior result section carries still resolves. Where an earlier append already used suffixes, the letters continue from the last one used. Several steps land in severity order, critical → major → minor, ties in the order phase 1 displayed them — which is also what "the later step" means in **Depends on** above. An append of **three or more** steps also carries one `### Checkpoint after Step N<x>` after the last of them, at the cadence and in the shape `plan-task` § *Add Checkpoints* owns: the eventual `implement-task` run performs its named integration assertion there, then the checkpoint's health boundary. Fewer than three appends none.

**`## Scope` normally stays untouched.** The new-step row in `./reconciliation-session-to-docs.md` § *`reconcile-task` — session findings* closes with the obligation to keep `## Scope`'s goal-ID partition total, and a finding-step normally meets it by changing nothing: the defect is in work this plan shipped, so the goal it cites already sits on the `delivered:` side, and the `none (infra/refactor)` escape cites no ID at all. Two answers would falsify the partition, and both are settled in the round rather than written around — an ID the plan **defers** joins `delivered:` only on the engineer's word in that round, and an ID absent from `goals.md` is outside this phase's write surface, so the finding is declined and "Not reconciled" names what would have to happen first (the user adding the goal, or `reconcile-task`'s new-goal row (`./reconciliation-session-to-docs.md` § *`reconcile-task` — session findings*) adding it on a confirmed wording). The prose half of `## Scope` is settled in the same round and never written: a finding whose fix falls in what the plan puts **out of scope** is declined by default, appending it being a step the plan's own boundary refuses, and "Not reconciled" names what would take it — `plan-task` to re-scope, or the task that owns that surface.

**The target's status.** `executing` and `blocked` plans take the append with **both statuses untouched** — appending steps enriches a paused plan and resumes nothing, so a `blocked` pair keeps its `**Blocked:**` section and the record lands in the result file that status already implies. A `done` or `in-review` pair returns to `executing` on both files, dropping the result's closing `**Completed:**` line where one exists (a `done` result carries it; an `in-review` result never does), and it flips **before the first step is written**: appending work is what makes a finished plan unfinished, so the flip follows from the content changing, not from a claim about what is built — which is why `./reconciliation-session-to-docs.md` § *Strengthen only on verified evidence* is not in play, that rule governing claims that something *is* built. The edge is registered in `./status-transitions.md`. Prior result sections stay as written — a `## Acceptance` or an `**In review:**` section included — superseded by this run's entry per `./reconciliation.md` § *The record*'s append-only rule, never rewritten. `to-do` and `skipped` plans never reach this phase, and neither does a target whose companion `result.md` is absent — the composite refuses all three in its Setup, before phase 1 spends the review. That third refusal is what lets every status above name the result file it writes to: a status implies a companion by the pairing rule, and the drift where one is missing (`./task-lifecycle.md` § *Pairing rule*) is repaired by the docs → reality composites rather than worked around here.

**The record.** One `## Reconciliation — YYYY-MM-DD` entry per run, in the format `./reconciliation.md` § *The record* fixes, naming each appended step and the finding behind it — that pairing is the one place a step's provenance is recorded. That format closes each bullet with the finding behind the edit and a bracketed sweep tag; this phase runs no sweep, so the bracket carries the finding's **verdict** instead — always `[Confirmed]`, the only verdict that reaches a file — beside its severity and `file:line`, which is what makes the bullet re-checkable against phase 1's Output. A reopen is its own bullet, naming both files and the dropped `**Completed:**` line, since the flip is an edit like any other. Close by refreshing `## Current state` per § *Current state refresh*, its `**Next:**` naming the appended work; a result just flipped back to `executing` is a live result again, as that section's last bullet says. The run's "Not reconciled" list stays in the printed change list (§ *Sequence and output*) and never enters the entry — a finding that produced no step leaves no trace in the folder.

A `reconcile-task` run ending over the size trigger raises the compaction proposal as one more judgment item, per `./reconciliation.md` § *Compaction (size trigger)*, which this direction adds nothing to. The trigger is scoped to that member by the shared rule's own wording, so the composite never raises it — its round holds the accepted findings and nothing else, and an append that pushes a result over the trigger is picked up by the next `reconcile-task` run on the folder.
