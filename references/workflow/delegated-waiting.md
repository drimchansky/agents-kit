# Delegated Waiting

How an agent collects asynchronous work it launched: delegated agents and shell commands. What an outcome means stays with the launching contract.

## How to wait

**Use the launch surface's completion mechanism.** Carry on with independent work while a launch runs. When none remains, receive its notification or collect its command session through the host primitive below.

**Watch every awaited shell command for silence.** Before ending a turn to await a background shell command, arm a silence watch through § *Shell commands*. Watch the command's output and every log the command writes progress to. The watch notifies once for each full interval in which none of them changes. Keep it armed until the command is collected. The interval is five minutes. State a longer interval at launch when the command is known to stay quiet longer. A program's own deadline does not lengthen the interval when a step inside it can block past that deadline. A server or other process that the agent stops itself, instead of awaiting its exit, keeps the watch until its ready condition holds. Then stop the watch. The process takes no watch once ready.

**Report where each launch stands.** At every check-in while something is outstanding, give one line per launch: launched, still running, silent, or collected. Report a command under a silence watch as still running until its measured silence reaches its interval. Once it has, report it as `⚠️ Silent since <time>` with the last line written to its output or watched logs (`./user-facing-messages.md` § *Blocks*). Measure silence as the watch does (§ *Shell commands*): from the latest of the launch and the newest change to the output or a watched log. On Codex, use the first check's time in place of the launch time. Use as `<time>` the moment measured silence began. When the command has written no line yet, give its last output as `none yet`. Report a command whose watch is missing (as defined under **A launch whose host names no surface below runs in the foreground**) as still running, and state that its watch is missing. Report a server or other process that the agent stops itself as still running and ready once its ready condition holds. An unreported wait cannot be called off.

**Check a silent command for activity.** When first arming the watch, sample the command's process tree: each process ID with the cumulative CPU time it has used. The tree's root is the process whose ID the launch wrote to its pid file (§ *Shell commands*). On Codex, every activity sample of a shell command is unavailable. Judge such a command on silence alone. Before using each sample, read the recorded start time from that file. Require the process with the recorded ID to show that start time unchanged. A sample is unavailable when the file is missing or empty, its identity line is missing, or no running process has its ID. A sample is also unavailable when the process's start time differs from the recorded start time. When the arming sample is unavailable, record it as unavailable. An unavailable arming sample does not by itself make the command silent. After each silence notice, take a new sample before waiting again. When the new sample is unavailable, report the command as silent with its sample unavailable and judge it on silence alone. Otherwise compare it with the previous sample only when that sample is available and was taken after the newest change to the command's output or watched logs. When the previous sample is unavailable or predates that change, report the command as silent with activity not yet measured. Keep the new sample as the baseline and judge activity at the next notice. When comparing, count the command as working when a process in both samples used more CPU time or a new child process appears. A new child process is one absent from the previous sample. When neither signal moved, tell the user the command shows no activity. Name that evidence: its process is alive, its CPU time did not grow between samples, no new child process started, and no watched file changed. Say it may be hung or waiting on the network, a lock, or another process. When either signal moved, report the command as silent but working and name the signal that moved. Then keep waiting with the watch armed. Whether to stop or relaunch the command stays with its launching contract.

**A launch whose host names no surface below runs in the foreground**, at the point its contract would have launched it, and is reported on collection like any other. So does a shell command whose silence watch cannot be armed because the watch tool is missing. If the host then moves that command to the background, collect it as usual. On both hosts, a watch that cannot be armed, is denied, or ends early counts as a missing watch. An early end means a Claude Code `Monitor` ends before its `timeout_ms` without `TaskStop`, or a Codex watch check fails. Report a missing watch on a command running in the background to its launching contract as a gap. Do not re-arm a missing watch. When the watch is missing after a shell command's background launch, keep the command running and collect it as usual. A server or other process that the agent stops itself does not run in the foreground. When its silence watch cannot be armed, do not launch it. When the watch is missing after its launch, stop it under § *Per-host primitives*, including its cooperative-termination fallback. A missing surface or watch tool withdraws the background option, not the reporting duty. A missing surface or watch never licenses a foreground `sleep`.

## What is not a wait

**A blocking foreground `sleep`.** It buys no signal, and the Claude Code harness refuses it outright. Where a condition has to be watched rather than notified, put the watch itself in the background.

**A condition the awaited work will never satisfy.** An `until` loop on a path nothing writes, a grep for a marker never printed, a filter matching only the success line of a job that can also crash. Before arming a conditional wait, name what writes the condition and what the watch emits if the work dies; with no answer to either, do not wait on it.

**A shell-command wait that misses a crash or a hang.** Before arming any wait on a background shell command or a condition it should produce, meet the crash requirement of **A condition the awaited work will never satisfy**. Also name what the wait emits if the command hangs. Arm no wait without both. Collecting a command with a missing watch is exempt once the missing watch is reported as a gap (§ *How to wait*). Awaiting the command's completion reports a crash through its exit status. The silence watch from § *How to wait* reports a hang. On its own, an `until` wait on a marker the command prints on success reports neither a crash nor a hang before the marker. Arm such a wait only beside the command's silence watch, and still collect the command's exit status.

## Per-host primitives

When no stop primitive is available for a launch, request cooperative termination and collect confirmation. A collected completion also confirms termination.

- **Claude Code**: a subagent launched through the `Agent` tool runs in the background and notifies on completion. For a condition, use `Monitor` where each occurrence is worth a notification. `TaskStop` stops a running background task by its ID.
- **Codex**: a subagent on the multi-agent surface notifies on completion; `wait_agent` additionally blocks for a bounded window when the result is on the critical path. It takes `timeout_ms` and returns empty on expiry; an empty return is not a finished agent, so re-enter the call or leave it to the notification. `close_agent` shuts a subagent down and returns its status before shutdown. A host exposing `interrupt_agent` instead stops the agent's current turn, returns its previous status, and leaves the agent available. Codex has no stop primitive for a shell command launched through § *Shell commands*. Request its cooperative termination. Confirm the stop through a `write_stdin` return carrying an `exit_code`. When the stop cannot be confirmed, report the command as outstanding and its termination as unconfirmed.

## Shell commands

Run each command in the working root its launching contract names. On Claude Code, launch it as `echo $$ > <pid-file>; ps -o lstart= -p $$ >> <pid-file>; <command>`, without `exec`. Pass that whole line as the `Bash` command. On Codex, pass the plain `<command>` as `cmd`, with no pid file. The pid file records the shell's ID, then an identity line with its start time. `$$` names the shell that runs the command, the root of the process tree the activity check samples (§ *How to wait*). Set `<pid-file>` to an absolute path in the agent's scratch area, beside the command's own scratch files when it has them. Give each launched command its own `<pid-file>` path, including commands launched together. When the agent's scratch directory is `none (<reason>)` (`./agent-scratch.md` § *Agent rules*), launch the plain command without the pid-file prefix. Every activity sample of that command is then unavailable. Judge it on silence alone (§ *How to wait*). Collect the command's output and exit status before interpreting its outcome. Remove the pid file once the command is collected or stopped.

On both hosts, count a watched log that does not exist yet as unchanged. Its absence does not fail a silence check.

- **Claude Code**: launch with `Bash` and `run_in_background`. The session resolves `<kit-root>` once, when it first needs the silence-watch command `node <kit-root>/scripts/silence-watch.ts`, using an absolute path. It resolves through `./task-store.md` § *Resolving `<kit-root>`* and may ask there. It passes that command to every delegated agent it launches that runs on Claude Code, or `none (<reason>)` when no kit root resolves. A delegated agent that runs on Codex receives `none (unused on Codex)`. Choose by the host the delegated agent runs on, not the session's host. A Codex session passes the command to a `claude -p` executor. A delegated agent, launched under another agent's packet, uses the packet's silence-watch command. A packet item of `none (<reason>)` counts as no kit root; do not resolve it again. Without a packet item, the delegated agent uses only config's `kitRoot` or its own plugin install root. It never asks for the checkout path. When no kit root resolves, treat the watch tool as missing (§ *How to wait*). Arm the silence watch as a `Monitor`, appending `--interval <seconds> <output-file> <progress-log>...` to the watch command. Pass the interval from § *How to wait* in seconds. List the output file the launch result names and every progress log. Set its `timeout_ms` to `1800000`, or to the host's maximum when that is lower, such as `600000` in a `claude -p` run. The watch's modification-time checks and reading the output file's last line at a silent check-in are the intended exception to the launch result's notice against polling or reading that file. `../scripts/silence-watch.md` defines how the watch measures silence and when it prints a line. Re-arm the same command only on expiry. On re-arm, measure the command's silence as § *How to wait* does. If that silence crossed a multiple of the interval since the latest silence notice, treat the re-arm as one silence notice. Before the first silence notice, use the watch's first arming in its place. Then report where the command stands and check it for activity as § *How to wait* requires. An early end follows the missing-watch rule in § *How to wait*. The completion notification supplies the exit status and names the output file. Read that file before interpreting the outcome. Stop the `Monitor` with `TaskStop` when the command is collected, stopped, or ready. For a condition, run a background command that exits when the condition holds.
- **Codex**: launch with `exec_command({cmd:<command>, workdir:<root>, yield_time_ms:1000})`. An immediate `exit_code` completes the command. When it returns `session_id`, call `write_stdin({session_id, chars:"", yield_time_ms:300000})` on that same session until an `exit_code` arrives. Preserve output from each response. Arm the silence watch by running its check once before the first `write_stdin` call. The check is a short separate `exec_command` that prints the current time and each watched log's modification time. Run it again after each return without an `exit_code`. If the check fails, follow the missing-watch rule in § *How to wait*. Silence is the time since the latest of the first check, the last return with new output, and the newest change to a watched log. Take a return's time from the check that follows it. An empty return with unchanged logs does not reset silence. Measure silence in time, not in the number of returns. Each time silence reaches another multiple of the interval, treat that check as one silence notice. Report the command's status and check it for activity as § *How to wait* requires. Do not relaunch or end the turn expecting a notification.
