# Reconciliation: Session → Docs

The direction `reconcile-task` writes in. It runs on the shared mechanics in `./reconciliation.md`, which this file does not restate — consent model, who runs the reference sweep, record and annotation formats, `plan.md` openings, run sequence, and § *Strengthen only on verified evidence*, the verify-and-write engine every advance this direction makes goes through.

Findings come from reviewing the current session against the docs, so this direction *enriches*: it writes information the docs are missing.

## Write surface

All four core task files, plus the sweep's `observations.md` rewrite — `reconcile-task`'s surface, and so the direction's. Never the upstream `ticket.md`, read-only (a changed ask is surfaced for the user), and never `diagram.md` or a doc task's deliverable (`./reconciliation.md` § *Authored surfaces are never written*). `result.md` per `./reconciliation.md` § *The record*. `plan.md` — the five shared openings, plus **two additions**:

- a **new step**, only through a confirmed judgment item (docs → reality closes against this because redesign is out of scope there; here, enriching the plan is the point), inserted without renumbering per the step-stability rule;
- a **new open-question line** appended to `## Open Questions` — auto, pure enrichment, distinct from the answered-question *annotation* the five already cover.

`CONTEXT.md` prose sections (not annotation-only) and `goals.md` are writable too, but only through a **confirmed** judgment item. Pure enrichment auto-applies: a new external reference into `## References`, an answered open question annotated in `## Open Questions`, a new open question appended there, session narrative appended to `result.md`. Each enrichment lands in the fact's **home file only** (`./reconciliation.md` § *One home per fact*): a session decision goes to `CONTEXT.md` *or* the affected plan step, whichever the homes rule names, and an answer is annotated where its question lives, never mirrored into both.

## Grounding docs change by confirmation, never silently

Writing `goals.md`, `CONTEXT.md` prose (`Recommended Direction`, `MVP Scope`, `Not Doing`, `Key Assumptions`), or a step's scope — anything that redefines scope or acceptance — is a **judgment item**: it goes through the batched confirmation round, never an unprompted auto-apply. `goals.md` edits obey the durable-ID scheme in `./task-goals.md`: a new goal takes the next free `G<n>`, IDs are never renumbered and a retired ID never reused, and the file keeps its no-`**Status:**` / no-`## Description` shape.

## `reconcile-task` — session findings

Findings come from diffing the session against the docs, plus the reference sweep (`./reconciliation-sweep.md`). Route values — **auto**, **ask**, **verify**, **flag only** — are `./reconciliation.md` § *The mapping legend*, unchanged here.

- **New reference / spec / ticket surfaced in session**, absent from `## References` → **auto**: append it to `CONTEXT.md`'s `## References` (label + URL, plus a short note of what it is).
- **Open question answered in session** → the shared answered-question annotation format (**auto** when unambiguous, **ask** when interpretation is needed). A goal marked `_(unresolved: …)_` changes only via the new-goal row below.
- **Cited link broken** (`block`) → **auto**: the shared broken-link annotation format, or the new URL when a redirect target is known. A carried-forward `block` routes nothing new (`./reconciliation.md` § *Annotation formats*).
- **Cited reference answers an open question** (`warn`) → the shared answered-question annotation format, citing the fetched source; **auto** when it answers unambiguously, **ask** when it needs interpretation. Same treatment whether the answer came from the session or the fetch — the question's home file decides where it lands.
- **Cited reference materially changed or gone** → the whole row is `./reconciliation.md` § *Cited reference changed*, this direction taking its **session → docs** delta: a changed reference contradicting `CONTEXT.md` prose is an **ask**, per the grounding-docs rule above. "Not reconciled" names `implement-task` wherever the row flips no status.
- **Never-annotated surface changed or broken** — the trigger and the rule are `./reconciliation.md` § *Never-annotated surfaces*, which governs here unchanged: **flag only**, owner named, `## Reconciliation` entry only when one is already being written. "Not reconciled" names the owner that rule names — the user for `ticket.md` and for the `**Published:**` line, `implement-task` for a pause section.
- **New open question raised in session** → **auto**: append it to `## Open Questions` in the file the question belongs to (`./reconciliation.md` § *One home per fact*) — `CONTEXT.md` when it questions the grounding, `plan.md` when it questions the plan's own execution.
- **Session narrative** — what was explored, tried, or decided that isn't itself a state change or a grounding rewrite → **auto**: append a `## Reconciliation — YYYY-MM-DD` section to `result.md`, creating the file and flipping the plan `to-do → executing` when work is evidenced, per `./task-lifecycle.md` § *Companion result file*.
- **Step completed this session** → **verify**: re-check its full unit-outcome tier — the `**Verify:**` criterion plus the per-unit checks the resolved domain's `verification.md` adds (`./execution-loop.md` § *Two verification tiers*); the criterion alone is not the tier. Passes → check `- [x]` in `plan.md` and record the evidence in `result.md`. Fails or unverifiable → surface, leave `- [ ]`.
- **Goal met this session** → **verify**: re-check the goal's acceptance behavior. Passes → record it `met` (in `## Acceptance` when finalizing, otherwise noted in the Reconciliation entry). Advance `executing → done` only when the full gate passes against every goal, and only once `./reconciliation.md` § *Strengthen only on verified evidence*'s integrated-health precondition is satisfied and its result recorded, and its diagram stop clears; when unmet goals are all `(external)` ones still awaiting their proxy, finalize to `in-review` instead — which is a completion claim over the agent-verifiable work, so it owes both. Fails → surface, no flip.
- **`(external)` goal confirmed this session** (the user reports the deploy check, the client sign-off, the receipt) → **verify**: re-check it against that best-available proxy per `./acceptance-criteria.md`. Passes → if another `(external)` goal remains `pending external`, record the new `met` verdict, with the proxy, in the `## Reconciliation` entry, which supersedes the prior `## Acceptance` line (never edit that line in place — the append-only rule holds). If it would close the last pending `(external)` goal, first run `./reconciliation.md` § *Strengthen only on verified evidence*'s fresh current-run integrated-health boundary: **when that boundary passes**, append the proxy-backed `met` verdict, record the fresh health evidence, and advance `in-review → done` with the closing `**Completed:**` line as one finalization; **when it fails**, record the proxy receipt and the health failure without superseding the authoritative `pending external` verdict, and leave the task `in-review`. Proxy fails or no proxy → leave `pending external`, task stays `in-review`.
- **New goal, or a reworded goal, decided in session** → **ask**: confirm the exact wording, then write `goals.md` per the durable-ID scheme above.
- **Changed direction / MVP scope / Not Doing / Key Assumptions** → **ask**: confirm the exact prose, then write the matching `CONTEXT.md` section. Leave the `**Status:**` origin marker untouched.
- **Changed step scope / new step / changed Verify criterion** → **ask**: confirm, then write `plan.md` within the confirmed finding's scope, updating `## Scope`'s goal-ID partition to stay total.
- **Changed ask** → flag only: the session shows the product requirement itself differs from what `ticket.md` states. The ticket is user-owned; surface it for the user to update, then re-derive goals via `plan-task`. Reconciliation never rewrites the ask.
- **Structure changed this session in a way `diagram.md` doesn't show** (the session nominates) → **flag only** per `./reconciliation.md` § *Authored surfaces are never written*, with the finalization stop the standing divergence triggers in that file's § *Strengthen only on verified evidence*. Deciding a diagram is now *warranted* is a `plan-task` call, not a reconciliation one.
- **Deliverable content decided this session but absent from the file** (doc tasks) → **flag only** on that same exclusion; "Not reconciled" names `implement-task`. A stale *published copy* is the `**Published:**` row above, not this one.
- **Work discussed but not done** → flag only: it isn't verified, so it isn't recorded; "Not reconciled" names `implement-task`.
