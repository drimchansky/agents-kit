# Reconciliation: Session → Docs

`reconcile-task` enriches task docs with current-session findings. Shared mechanics: `./reconciliation.md`.

## Write surface

Write context, goals, plan, result, ticket, and inherited group files. Never write `observations.md`; only the composites' sweep rewrites it (`./reconciliation-sweep.md` § *Ledger*). A confirmed compaction also writes its result snapshot outside the folder, under `./reconciliation.md` § *Docs, not the world*. Exclude deliverables (`./reconciliation.md` § *Authored surfaces are never written*), Published lines, and active pause sections (§ *Never-annotated surfaces* there). A superseding In review section appends after the active one under the *In review superseded* row below. Results follow § *The record* there.

Use the five shared plan openings, plus:

- **New steps**, **judged**: insert without renumbering existing steps.
- **New open questions**, **auto**: append in Open Questions.

Judge context prose, goals, and step scope under `./reconciliation.md` § *Grounding docs change on evidence, never silently*. Ticket/group content additionally follows § *The upstream ask is writable, and never rewritten quietly*. Annotation-only edits retain § *Annotation formats*' route.
Every judged row follows the shared consent model; an unresolved impactful choice writes no dependent change before the answer.

Auto-enrich references, questions, and result records of session decisions, outcomes, and state changes at their home (`./reconciliation.md` § *One home per fact*).

## `reconcile-task` — session findings

Use session evidence only. Run no reference sweep or freshness-only fetch of a cited URL. A **verify** row still opens any URL its required checks name. Routes follow `./reconciliation.md` § *The mapping legend*. A link fact the session observed takes that session observation as its source in place of a sweep tag.

- **New reference/spec/ticket** — **auto**: append label, URL, and short description to context References when absent.
- **Open question answered in session** — use the shared answer format: **auto** if unambiguous, otherwise **judged**. Keep the full decision evidence dated and reachable from concise current guidance, including on a to-do task with no result (`./one-home.md` § *One home per fact*). Goals' `_(unresolved: …)_` uses the goal-change row.
- **Cited link observed broken in session** — **auto**: source the session observation, such as a 404, and use the shared broken-link format or the known redirect target (`./reconciliation.md` § *Annotation formats*).
- **Cited page read in session answers an open question** — source the session observation and use the shared answer format at the question's home, citing that page: **auto** if unambiguous, otherwise **judged**.
- **Cited reference observed changed or gone in session**, such as a cited PR's new head — source the session observation and apply `./reconciliation.md` § *Cited reference changed*. Where that section leaves status unchanged, name `implement-task` under Not reconciled only for a change that may mean unverified progress or a lifecycle change. Such changes include a merge, a closure, or a gone reference. A head move names no owner. It takes that section's Pointers refresh, plus the *In review superseded* row when it moves an in-review plan's expected source.
- **Never-annotated surface observed changed or broken in session** — **flag only** under `./reconciliation.md` § *Never-annotated surfaces*: user for Published, `implement-task` for pauses. An in-review plan's moved expected source takes the *In review superseded* row instead.
- **Shared constraint changed or contradicted** — **judged**: apply evidence-settled corrections and prior decisions; otherwise leave an impactful precedence choice pending. Write settled group edits under upstream-ask terms and local scope/Verify, context, or goals at home. Quote both statements with their sources, cite the group file by its path from the selected root, and record which side lost. Flag redesign for `plan-task`.
- **New open question** — **auto**: append grounding questions in context, execution questions in plan.
- **Session narrative** of decisions, outcomes, and state changes that no other row covers — **auto**: append Reconciliation to result under `./reconciliation.md` § *The record*. When work is evidenced, create result; **verify** before taking `to-do → executing` under `./task-lifecycle.md` § *Companion result file* and the shared advance engine.
- **Step completed this session** — **verify** Verify and domain per-unit checks (`./execution-loop.md` § *Two verification tiers*). Pass: check and record evidence. Otherwise leave pending; flag **Needs work**, naming `implement-task`.
- **Goal met this session** — **verify** acceptance. Record passing `met` in Reconciliation, or Acceptance when finalizing. Finalization requires all goals, applicable engineering live checks, and fresh health under `./reconciliation.md` § *Strengthen only on verified evidence*. Its delivered-source selector applies to deployable engineering `in-review → done`; documentation and supported local-only engineering use current work-product health. Enter in-review for downstream verification, including checks without goal IDs; enter done only when all pass or have supported N/A. Failed work routes **Needs work** to `implement-task`, with no status flip.
- **`(external)` goal confirmed** — **verify** its best-available proxy (`./acceptance-criteria.md`). With downstream checks pending, append its proxy-backed `met` verdict in Reconciliation, superseding prior Acceptance without rewriting it, then apply the *In review superseded* row. Before the last pending item closes, verify engineering live checks and freshly pass integrated health on the surface selected by `./reconciliation.md` § *Strengthen only on verified evidence*. Missing delivered-source proof for deployable engineering stays pending, without a failed-health claim. Pass: append `met` and health evidence, take `in-review → done`, and write Completed together. An actual health failure records receipt and failure, preserves the authoritative pending state, and stays in-review. Failed or absent proxy also leaves that verdict and status unchanged.
- **Engineering live check resolved** — **verify** expected release, workload health, and frontend/backend behavior under `../engineering/acceptance-gate.md`. Append evidence or supported N/A in Reconciliation, and carry unresolved targets forward under the *In review superseded* row. An observed failure routes **Needs work** to `implement-task`; no completion advance or In review section follows it. The last passing check can close in-review only after all goals and fresh health pass on the selected surface (`./reconciliation.md` § *Strengthen only on verified evidence*).
- **In review superseded** — **auto** on an in-review plan when session evidence moves the expected source, such as a push's `git ls-remote` readback. It applies too when a pending item passes its verify row above while others stay pending. Append `## In review — YYYY-MM-DD` in the shape `./task-lifecycle.md` § *Companion result file* gives; when an In review heading already has that date, suffix the new one `(2)`, then increment. Directly below the new section's `**In review:**` line, write `**Supersedes:** In review — YYYY-MM-DD`, copying the replaced section's heading text with any same-day suffix, such as `(2)`. Use the source that session evidence establishes, such as the push readback head. Otherwise, use the source the result's delivery pointer names, when one exists (`./task-delivery-edges.md` § *Verification source after delivery*). If neither establishes a source, carry forward the active In review list minus items that passed this session. For deployable engineering work, also list source health as pending, naming missing proof, its owner, and next action (`./task-delivery-edges.md` § *Verification source after delivery*). List every applicable item not yet passed on that source: each pending `(external)` goal with its verifier, and each engineering check with its target, check, owner, and next action. A source-health check passed on a same-tree commit counts as passed on that source (`./task-delivery-edges.md` § *Verification source after delivery*). An `(external)` goal that passed only on another commit counts as passed on that source when that commit has the same tree and the goal's criterion and evidence name no specific revision or build. Otherwise, list that goal as pending with its verifier. For each goal reopened by a source change, append its `G<n>` `pending external` verdict and source change to this session’s dated Reconciliation entry. Supersede its earlier `met` without rewriting Acceptance. A deployment or live check that passed only against an older build is pending again until the observed release matches that source's build (`../engineering/acceptance-gate.md` § *Observe each applicable environment*). Leave the earlier section byte-for-byte and the plan `in-review`. When the last pending item closes, the finalization path above applies and writes no In review section. A failed check writes no section and routes **Needs work** to `implement-task`.
- **New, reworded, or retired goal** — **judged**: apply session-supported changes under the grounding rule; preserve durable IDs. Replace a resolved marker's alternatives with the selected current rule and a decision-record citation, preserving the acceptance outcome and historical alternatives. A goal written this run is never recorded `met` in the same run; that verdict waits for a later run's re-verification.
- **Changed direction/MVP scope/Not Doing/Key Assumptions** — **judged**: rewrite the matching context section; quote prior wording in the record.
- **Changed step scope/new step/changed Verify** — **judged**: edit within the finding; keep Scope's goal-ID partition total.
- **Changed ask** — **judged**: write the ticket on upstream-ask terms, with requester wording as evidence, both wordings quoted, and the section named. Refer uncovered criteria to `plan-task` under Not reconciled. Never fit the ask to built work.
- **Deliverable content decided but absent** — **flag only**, naming `implement-task`; stale published copies take the Published row instead.
- **Work discussed but not done** — **flag only**, naming `implement-task`.

A session that only explored, with no decision, outcome, or state change, is reported in chat and not recorded.
