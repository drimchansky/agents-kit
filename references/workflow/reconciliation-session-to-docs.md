# Reconciliation: Session → Docs

The direction `reconcile-task` and the composite `review-pr-triage-verify-reconcile` write in. It runs on the shared mechanics in `./reconciliation.md` — consent model, reference sweep, record and annotation formats, `plan.md` openings, run sequence — which this file does not restate.

Findings come from reviewing the current session against the docs — or, in the composite, from the Confirmed findings its review phase produced — so this direction *enriches*: it writes information the docs are missing.

## Write surface

All four core task files, plus the sweep's `observations.md` rewrite — `reconcile-task`'s surface, and the direction's maximum; `review-pr-triage-verify-reconcile` writes a strict subset, `plan.md` and `result.md` only, and sweeps nothing (its section below). Never the upstream `ticket.md`, read-only (a changed ask is surfaced for the user), and never `diagram.md` or a doc task's deliverable: authoring content is outside reconciliation in either direction, stated in full in `./reconciliation-docs-to-reality.md` § *Write surface*. `result.md` per `./reconciliation.md` § *The record*. `plan.md` — the five shared openings, plus **two additions**:

- a **new step**, only through a confirmed judgment item (docs → reality closes against this because redesign is out of scope there; here, enriching the plan is the point), inserted without renumbering per the step-stability rule. This is the opening `review-pr-triage-verify-reconcile` writes through, one step per accepted finding — its section below is that member's whole mapping;
- a **new open-question line** appended to `## Open Questions` — auto, pure enrichment, distinct from the answered-question *annotation* the five already cover.

`CONTEXT.md` prose sections (not annotation-only) and `goals.md` are writable too, but only through a **confirmed** judgment item. Pure enrichment auto-applies: a new external reference into `## References`, an answered open question annotated in `## Open Questions`, a new open question appended there, session narrative appended to `result.md`. Each enrichment lands in the fact's **home file only** (`./reconciliation.md` § *One home per fact*): a session decision goes to `CONTEXT.md` *or* the affected plan step, whichever the homes rule names, and an answer is annotated where its question lives, never mirrored into both.

## Strengthen only on verified evidence

This direction may **advance** state — check a `- [ ]` step `→ - [x]`, mark a goal `met`, flip `to-do → executing`, `executing → done` (or `executing → in-review` when the only unsatisfied goals are `(external)` ones still awaiting their proxy), or `in-review → done` — but only after **re-verifying** in-session the way `implement-task` would: a step's full unit-outcome tier (`./execution-loop.md` § *Two verification tiers*) and a goal's acceptance behavior, against the resolved domain's `verification.md` (`../engineering/verification.md` when the domain is code). Before any `reconcile-task` advance that presents the task as complete — `executing → done`, `executing → in-review`, or `in-review → done`, each of which reports implementation finished — the resolved domain's integrated-health recipe must freshly pass in the current reconciliation run on the current work product (`../engineering/verification.md` § *Two verification tiers* for code, `../documentation/verification.md` § *Integrated health — declared boundaries* for documents), regardless of whether this session changed work-product bytes. The durable record carries no exact work-product identity for an earlier boundary, so it cannot establish that earlier evidence belongs to the current state across runs; no earlier health evidence may be reused (`./execution-loop.md` § *Health boundaries*). A non-final advance — a step's box, a goal recorded `met` short of finalizing — owes its unit-outcome tier and no more, exactly as a step between boundaries does (`./execution-loop.md` § *Health boundaries*). **This clause is the one home for that precondition**; the rows below and the skills running this direction cite it rather than restating the trigger. Record the fresh evidence as the entry's `**Health:**` line (`./reconciliation.md` § *The record*). A step or goal it cannot verify this session stays unrecorded and is surfaced instead. It never advances state on a bare conversational assertion — witnessed-and-verified, or not at all. The one sanctioned exception: for a goal marked `(external)`, whose verification lives outside the session by design, the best-available proxy — the confirmation, receipt, or observed live state the user reports — *is* witnessed-and-verified evidence (per `./acceptance-criteria.md`), so `in-review → done` may advance on it.

## Grounding docs change by confirmation, never silently

Writing `goals.md`, `CONTEXT.md` prose (`Recommended Direction`, `MVP Scope`, `Not Doing`, `Key Assumptions`), or a step's scope — anything that redefines scope or acceptance — is a **judgment item**: it goes through the batched confirmation round, never an unprompted auto-apply. `goals.md` edits obey the durable-ID scheme in `./task-goals.md`: a new goal takes the next free `G<n>`, IDs are never renumbered and a retired ID never reused, and the file keeps its no-`**Status:**` / no-`## Description` shape.

## `reconcile-task` — session findings

Findings come from diffing the session against the docs, plus `./reconciliation.md` § *External reference check*. Legend: **auto** = obvious, applied unprompted; **verify** = only after re-verifying in-session per the strengthen rule above; **ask** = the batched confirmation round first.

- **New reference / spec / ticket surfaced in session**, absent from `## References` → **auto**: append it to `CONTEXT.md`'s `## References` (label + URL, plus a short note of what it is).
- **Open question answered in session** → the shared answered-question annotation format (**auto** when unambiguous, **ask** when interpretation is needed). A goal marked `_(unresolved: …)_` changes only via the new-goal row below.
- **Cited link broken** (`block`) → **auto**: the shared broken-link annotation format, or the new URL when a redirect target is known. A **carried-forward `block`** — this sweep's fetch failed, the tag coming from an earlier observation — routes nothing new.
- **Cited reference answers an open question** (`warn`) → the shared answered-question annotation format, citing the fetched source; **auto** when it answers unambiguously, **ask** when it needs interpretation. Same treatment whether the answer came from the session or the fetch — the question's home file decides where it lands.
- **Cited reference materially changed or gone** — `warn` (PR merged, ticket closed, doc rewritten) or `block` on a `**Pointers:**` entry → **auto** for the world-truth surfaces only: refresh the affected `**Pointers:**` entry in the Current state refresh — for a `block`, a dated gone/moved note keeping the identifier — and note the observation in the `## Reconciliation` entry when other edits already warrant one. Then:
  - never a status flip on its own: a merged PR is not the acceptance gate, and `blocked` clears when work resumes; "Not reconciled" names `implement-task`;
  - a changed reference contradicting `CONTEXT.md` prose is an **ask**, per the grounding-docs rule above;
  - a `block` on a `CONTEXT.md` or `plan.md` citing line stays with *Cited link broken*; a `warn`/`block` on a never-annotated surface takes the never-annotated rule instead of either;
  - **route each citing occurrence by its own surface** — a URL cited on two produces both outcomes, per the docs → reality row;
  - a **carried-forward tag routes no new edit**, and an already-correct gone/moved note is likewise a **no-op**, re-dated only when the observed failure itself changed (404 → moved, with a known target). A carried tag whose finding was **flag only or left unanswered** — the `CONTEXT.md`-prose contradiction above, once its ask is declined or unanswered — is re-reported with its finding, not just its ledger line.
- **Never-annotated surface changed or broken** (`warn` or `block` on `ticket.md`, a deliverable's `**Published:**` URL, or the active pause section) → `./reconciliation.md` § *External reference check*'s **never-annotated rule** governs here unchanged: **flag only**, owner named, `## Reconciliation` entry only when one is already being written. "Not reconciled" names the owner that rule names — the user for `ticket.md` and for the `**Published:**` line, `implement-task` for a pause section.
- **New open question raised in session** → **auto**: append it to `## Open Questions` in the file the question belongs to (`./reconciliation.md` § *One home per fact*) — `CONTEXT.md` when it questions the grounding, `plan.md` when it questions the plan's own execution.
- **Session narrative** — what was explored, tried, or decided that isn't itself a state change or a grounding rewrite → **auto**: append a `## Reconciliation — YYYY-MM-DD` section to `result.md`, creating the file and flipping `to-do → executing` when work is evidenced, per the pairing rule.
- **Step completed this session** → **verify**: re-check its full unit-outcome tier — the `**Verify:**` criterion plus the per-unit checks the resolved domain's `verification.md` adds (`./execution-loop.md` § *Two verification tiers*); the criterion alone is not the tier. Passes → check `- [x]` in `plan.md` and record the evidence in `result.md`. Fails or unverifiable → surface, leave `- [ ]`.
- **Goal met this session** → **verify**: re-check the goal's acceptance behavior. Passes → record it `met` (in `## Acceptance` when finalizing, otherwise noted in the Reconciliation entry). Advance `executing → done` only when the full gate passes against every goal, and only once § *Strengthen only on verified evidence*'s integrated-health precondition is satisfied and its result recorded; when unmet goals are all `(external)` ones still awaiting their proxy, finalize to `in-review` instead — which is a completion claim over the agent-verifiable work, so it owes that same precondition. Fails → surface, no flip.
- **`(external)` goal confirmed this session** (the user reports the deploy check, the client sign-off, the receipt) → **verify**: re-check it against that best-available proxy per `./acceptance-criteria.md`. Passes → if another `(external)` goal remains `pending external`, record the new `met` verdict, with the proxy, in the `## Reconciliation` entry, which supersedes the prior `## Acceptance` line (never edit that line in place — the append-only rule holds). If it would close the last pending `(external)` goal, first run § *Strengthen only on verified evidence*'s fresh current-run integrated-health boundary: **when that boundary passes**, append the proxy-backed `met` verdict, record the fresh health evidence, and advance `in-review → done` with the closing `**Completed:**` line as one finalization; **when it fails**, record the proxy receipt and the health failure without superseding the authoritative `pending external` verdict, and leave the task `in-review`. Proxy fails or no proxy → leave `pending external`, task stays `in-review`.
- **New goal, or a reworded goal, decided in session** → **ask**: confirm the exact wording, then write `goals.md` per the durable-ID scheme above.
- **Changed direction / MVP scope / Not Doing / Key Assumptions** → **ask**: confirm the exact prose, then write the matching `CONTEXT.md` section. Leave the `**Status:**` origin marker untouched.
- **Changed step scope / new step / changed Verify criterion** → **ask**: confirm, then write `plan.md` within the confirmed finding's scope, updating `## Scope`'s goal-ID partition to stay total.
- **Changed ask** → flag only: the session shows the product requirement itself differs from what `ticket.md` states. The ticket is user-owned; surface it for the user to update, then re-derive goals via `plan-task`. Reconciliation never rewrites the ask.
- **Structure changed this session in a way `diagram.md` doesn't show** → flag only: the diagram is outside this write surface too, so name the stale nodes or edges and name `implement-task`, whose gate re-check repaints it. A task with no diagram raises nothing — and deciding one is now warranted is a `plan-task` call, not a reconciliation one.
- **Deliverable content decided this session but absent from the file** (doc tasks) → flag only: the deliverable is outside this write surface for the same reason the diagram is — authoring it is plan work. Name the section and what it should carry; "Not reconciled" names `implement-task`. A stale *published copy* is the `**Published:**` row above, not this one. A task with no deliverable raises nothing.
- **Work discussed but not done** → flag only: it isn't verified, so it isn't recorded; "Not reconciled" names `implement-task`.

The direction's second member, `review-pr-triage-verify-reconcile`, has its own finding-type → edit mapping in `./reconciliation-verified-findings.md`; read it when running that composite's reconcile phase.
