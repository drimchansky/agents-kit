# Task migration

Preview one task or group folder. Apply the token to the same physical folder with the same selected root.

```
node scripts/task-migrate.ts [--root <store-root>] <folder>
node scripts/task-migrate.ts [--root <store-root>] --apply <preview-token> <folder>
```

Stdout is a JSON object. `folder` is the resolved directory. `changes` names files to create, replace, or remove. It lists the history file first, then other changed files, then removals. `removed` lists the files in `changes` that the apply deletes. `applied` is empty on preview and lists the published changes on apply. `skipped` lists legacy suffixed or case-variant role names that leave the entire folder untouched. A canonical plan and result beside a bare `spec.md` are converted; the spec and its plan header are preserved. `missingSnapshots` identifies notes whose original section could not be recovered. `moved` lists the source files and headings preserved in history.

The token binds the input and proposed output, the migration date, and the source files used. Exit 0 reports a preview, a completed apply, a skipped folder, or an unchanged rerun. On exit 2 read stderr. Changed inputs require a fresh preview. A refused file or failed operation supplies no completion proof.

The helper groups current result records by key in plan order, preserves prior heading lines, and links each checked step to its own record. Each result record heading carries the step title's link labels without their links. Inline code examples keep their text. A result link at the end of a wrapped What field moves to its checkbox line so the loader can resolve it. Shared evidence has one owning record. A legacy wait can be identified by its first `**Blocked:**` or `**In review:**` label line instead of its heading. Without a wait heading for the plan status, the last unassigned section with the matching label becomes the wait record. Reconciliation entries and other legacy kept sections never become the wait record. Superseded waits and unassigned sections go to task history. Reconciliation and `Health boundary` entries after Acceptance still go to history verbatim. Their latest goal verdict lines and last `**Health:**` field are also copied to the end of Acceptance. Each copied group follows its source heading in a text fence. The copies become the last statement for each key. Goal-change rows such as `goals.md § G2 — …` are not copied. A verdict in a Reconciliation entry before a later `Health boundary` entry is not copied. Without an Acceptance section, the helper creates one for these copies only on a done or in-review plan. In the plan and context, the helper moves sections headed `## Decision — YYYY-MM-DD: <topic>` to history. Missing evidence remains explicit. Links to removed task-local sections retain their original label text, including nested brackets, escapes, and inline code. Links to renamed records take their new anchors. If these in-place changes displace the original bytes of a task-local section, keep that section verbatim in history. The observations ledger and existing history entries are left intact.

Restore a named snapshot only from its regular UTF-8 file directly under the local kit snapshot directory and check its content hash. A path enclosed in backticks can name a snapshot whose filename contains spaces. An absent snapshot or unavailable original section is reported. Keep the unresolved note for recovery. The helper never changes the snapshots.

If a link changes before the first level-two heading, history also preserves the original file prefix. In a file without a level-two heading, it preserves the whole file. The report labels these entries `File prefix`.

The helper preserves every documentation deliverable identified by its Status header under [Doc-Task Files](../workflow/doc-task-files.md). For links in those files that migration would change, `manualLinks` reports the file, one-based line number, and line text for review. It also reports existing links when a superseded record and the surviving Current state or wait record share an anchor. Those links keep their spelling so the reviewer can check which record the author meant. Links to distinctly named superseded records retain only their labels.

When a legacy deliverable occupies `history.md`, preview and apply exit 2. Rename the deliverable to an unused task-local Markdown filename, update references to it, and preview again.

Apply only to a quiescent store with its requested restore point. Replacements are atomic per file. A failure rolls back its own published edits while they still match their proposed contents. On interruption inspect the restore point and any remaining `.task-migrate.lock` before another apply.

For a legacy result, the helper restores compacted sections before reading gates in their original order. A checked step's citation can identify evidence only when its file and fragment point into this result. The helper selects the earliest eligible checkpoint in plan order, otherwise the last Final gate. A checkpoint must record a passing outcome. A verification-only continuation keeps established coverage. Later implementation requires a new Final gate and a new covering gate for the affected step. A later failed gate invalidates the affected proof. A no-change gate uses the prior qualifying landed gate SHA for the selected repository. Its Notes retain that SHA. A bare SHA without the legacy marker supplies no proof.

The result template and each converted result carry a header marker. The helper preserves step commits in marked results. It also preserves existing step commits in unmarked fixed records when it finds no evidence of a legacy log. If the same unmarked records could represent either format, the helper leaves missing step SHAs unset. The preview lists steps with possible legacy coverage and unresolved repository choices in `unresolvedCommits`. A multi-repository gate goes through repository selection. A gate with one SHA labeled by repository, such as `docs SHA` before the SHA, goes through it when the pointers record a branch. A branch pointer uses the repository named before it in the same sentence. If the pointers name distinct branches or leave the repository ambiguous, the helper reports the affected steps and any no-change gate that needs its SHA.

For a marked result or an unmarked result identified as current, preview and apply exit 2 if a required result section is missing, a section heading is unknown or repeated, or a checked step lacks a link to its own result record. The helper reports the loader diagnostics and leaves the folder untouched. Use `/resume-task` to recover the records from evidence.

Preview and apply exit 2 when a result section would end inside an open code fence or HTML comment that hides a later record.

A dated settlement can follow a failed hand-over in the same checkpoint or Final section, or in a later section. The helper applies it to the latest commit attempt for the gate it names.

The same CLI and token apply to one group directory. `removed` names the old log. `moved` labels the whole old log `File prefix` and lists each copied Decisions section. The new history starts with the old log bytes and contains the prior Decisions section. Existing, different history refuses the write. A group without an old log gets no new history. The highest question ID in the old group file or log becomes Last id.

The helper updates or inserts the opening Last id field in Open Questions. Other occurrences, including examples, keep their original text. They still count toward the legacy maximum.

With `--root`, a plain task path such as `area/worker/result.md` or `area/worker result § Approval` starts at the selected store root. If the file is absent there, the helper tries the old group-relative spelling. Markdown links, paths starting with `./`, and shorthand such as `worker result § Approval` start at the group. Omitting `--root` keeps the single-folder lookup.

The helper removes log and task-record citations throughout each live decision. A link in the rule keeps its label. A parenthetical that serves only as a citation is removed in full. The helper removes shorthand such as `worker result § Approval` only when the named task file contains one matching section. Trailing citations supply the rule date when they establish one date and cite no restructure or compaction. Earlier citations in the same rule do not affect that date. Migrate groups before their tasks when an undated citation needs its original task section to establish the date.
